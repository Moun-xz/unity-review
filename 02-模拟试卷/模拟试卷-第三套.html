一、案例分析题30 分 · 每题 6 分

第 1 题（6 分）· 你是美工第 1、4 章

策划要一面石墙，外形要「凹凸不平、有裂纹」，但引擎里只能放一个几百面的模型。你要用美术手段把细节补出来。

  1. 从原画到进引擎，美工最终要交出哪几样文件？（写出交付清单）
  2. 同一个模型上，法线贴图、凹凸贴图、高光贴图分别解决什么问题？
  3. Texture、材质、Shader 三者是什么关系？换其中哪一个会改变「算法」？
参考答案课件 01 slide 15~23 / 课件 04 材质与贴图

2 分交付清单：① 模型（低模，面数受控）② UV（拆分好，不重叠不拉伸）③ 贴图（基础色 / 法线 / 高光等）④ 材质球（Material，里面指定 Shader 并把贴图塞进对应槽位）。
（课件 01 建模九步的收尾就是：低模拓扑 → UV 拆分 → 烘焙法线贴图 → 材质与纹理制作 → 渲染调灯光）

2 分三种贴图：
① 法线贴图：RGB 三个通道记的是每个像素的法线朝向，光照按这个朝向算，于是平面看起来有凹凸——模型面数一点没加。
② 凹凸/高度贴图：只记高低（灰度），靠它做视差或置换；它本身不改法线，效果比法线贴图"钝"。
③ 高光贴图：记哪里反光、反多强（或 PBR 里的 Metallic / Roughness），决定石墙是"干燥粗糙"还是"湿滑发亮"。

2 分三者关系：Texture（图片）是原料 → 材质（Material）是配方，把若干贴图塞进 Shader 的槽位 → Shader 是算法，决定这些原料怎么参与光照计算。
所以：换贴图 = 换原料；换材质 = 换另一套配方；换 Shader = 换算法（比如从 Standard 换成 Unlit，物体就不再受光）。

第 2 题（6 分）· 你是关卡美术第 3 章

要做一张赛道地图：中间是平坦的场地（高度 50），四周起伏，地面要有草地、砂石、道路三种质感；还要能从白天切到夜晚。

  1. 导入系统自带的地形资源后，怎么做出一块高 50 的平地？导入时报错该怎么处理？
  2. 地面那三种质感怎么加上去？
  3. 灯光有哪几种类型、分别用在什么场合？哪种不能做实时光照？静态场景怎么省性能？
参考答案实验二 第 1 步 / 课件 03 slide 11~15、31~37

2 分地形与报错：
① 先 导入 Environment（环境）资源包，再在场景里 Create → 3D Object → Terrain 建地形；
② 选中地形，用 Flatten（Set Height）把整块地统一抬到 50，得到平整场地（要挖湖就在别处再做凹陷）；
③ 导入报错：只按课上讲的方法修与版本相关的那条错误，其余错误直接 Clear 清掉即可（实验二第 1 步原话「导入地形资源后需要根据上课所讲的方法修改版本错误」）。

2 分三种质感：用 Paint Texture（绘制贴图）→ Layer → Create Layer。第一层是基础层（草地），再逐层叠加砂石、道路；每层可选不同画刷，用笔刷大小 / 不透明度（强度）/ 角度去画。图层可以整体 Replace 替换。

2 分灯光：
① Directional（方向光）= 太阳，照全场景，白天/夜晚主光都用它；Point（点光源）= 灯泡、爆炸光；Spot（聚光灯）= 手电筒、路灯、壁灯；Area（区域光）= 面光源。
② Area Light 不能做实时光照，只能用于光照贴图烘焙。
③ 省性能：静态场景把灯光设成 Baked（烘焙），先 Edit → Project Settings → Player → Color Space 改 Linear，再到 Window → Rendering → Lighting → 生成 Baked Lightmap，运行时就不用逐帧算光照。

第 3 题（6 分）· 你是程序（推箱子）第 5 章 + 第 2 章

关卡规则：箱子能被推动、松手要停住不能一直滑；玩家踩到机关要弹开一扇门；墙必须挡住人。

  1. 刚体上哪些参数决定「推得动 / 推不动 / 会不会自己一直滑」？各调大调小会怎样？
  2. 撞墙和踩机关，分别用 OnCollisionEnter 还是 OnTriggerEnter？触发器的三个条件是什么？
  3. 物理相关的代码为什么放在 FixedUpdate？放 Update 会怎样？
参考答案课件 05 刚体与碰撞 / 课件 02 slide 28 生命周期

2 分刚体参数（每个都要说"往哪调、什么感受"）：
① Mass 质量：越大越难推、被撞后动得越少（箱子调重、人调轻）；
② Drag 阻力：越大越快停（想要"松手就停"就调大，想要冰面就调小）；
③ Angular Drag 角阻力：防止物体被撞后一直打转；
④ Use Gravity：取消勾选就不受重力（漂浮平台用）；
⑤ Is Kinematic：勾上后物理引擎不再算它，位置只能靠脚本改——适合被代码驱动的平台、机关门。

2 分两种判定：
① 撞墙要「挡住、弹开」→ 用 Collision（OnCollisionEnter / OnCollisionStay / OnCollisionExit），参数是 Collision；
② 踩机关只要「经过就触发」→ 用 Trigger（OnTriggerEnter(Collider other)），物理上不阻挡；
③ 触发三条件：双方都有 Collider + 至少一方有 Rigidbody + 至少一方勾了 Is Trigger。少一条就既不触发也不碰撞。

2 分FixedUpdate：物理引擎按固定步长（默认 0.02s，即 50 次/秒）算，所以加力、改速度应该写在这里，物理表现才和帧率无关。
放 Update 里：帧长不定（60fps 和 30fps 一步的时间不一样），同一个力在不同机器上推出来的距离不同；掉帧时还会出现"一帧走很远、穿模"的现象。
（Update 里读输入、算逻辑，FixedUpdate 里对刚体施力，这是固定搭配。）

第 4 题（6 分）· 你是特效与动画第 6、7 章

做一次炮塔爆炸：要「先整个炸开、碎片飞出去，然后慢慢变暗变小消失」；另外角色被打中要后仰一下再站起来。

  1. 爆炸效果用粒子系统的哪几个模块？每个模块负责什么？（写模块名 + 关键参数）
  2. 粒子模块分 over Lifetime 和 by Speed 两类，区别是什么？
  3. 「后仰一下」这种只播一次的动作，Animator 参数该用哪种类型？和 Bool 有什么区别？
参考答案课件 06 slide 9~15（原话）/ 课件 07 动画参数

3 分爆炸用这五个模块：
① Shape（形状）：定发射器形状 —— 球形/半球/圆锥/立方体/网格，爆炸用 Sphere，让碎片往四面八方飞；
② Emission（发射）：定发多少 —— 用 Rate over Time 控制每秒颗数，想「一次性炸」就设成很短时间的高发射量；
③ Velocity over Lifetime：定飞的过程 —— 初速大、随生命周期衰减，才像"炸开再停下"；
④ Size over Lifetime：定大小变化 —— 用曲线做「先大后小」，碎片逐渐消失；
⑤ Color over Lifetime：定颜色变化 —— 从亮黄/橙渐变到暗红、最后 alpha 归零。
（再加 Renderer 渲染模块选材质和混合模式，决定是"发光叠加"还是"普通贴图"。）

1 分两类模块的区别（课件原话）：over Lifetime 像"花开花落的一生"——在粒子整个生命周期里按 0→1 连续变化；by Speed 像"跑龙套"——只有粒子的速度满足条件时才执行（速度快就更亮/更大/转更快）。

2 分动画参数：用 Trigger（SetTrigger("Hit")）。
区别：Trigger 是"一次性的信号"，被触发后自动复位，适合"后仰一下""开一枪"这种播一次就完的动作；Bool 是"持续状态"，设成 true 后会一直保持，直到手动改回 false，适合"是否在跑""是否蹲下"。
（Float 用于融合树的连续量，如 Speed；Int 用于多状态枚举。）

第 5 题（6 分）· 你是 UI 与声音第 8 章 + 第 3 章音频

做一个设置界面：要能在手机竖屏和电脑 16:9 上都不变形；按钮要能点；还要有背景音乐和按钮点击音。

  1. Canvas 有哪三种 Render Mode、分别用在哪？为什么在 Canvas 里改不了 X/Y？
  2. 界面要在不同分辨率下都不变形，靠什么？（说出两个以上机制）
  3. 背景音乐和按钮音怎么配？Audio Listener 一个场景能有几个？音乐和音效分别用什么格式？
参考答案课件 08 slide 5~6、17~18 / 课件 03 slide 39~41

2 分Canvas 三种渲染模式：
① Screen Space-Overlay：永远盖在画面最上层，不受相机影响 —— 做 HUD、菜单这类纯界面；
② Screen Space-Camera：按指定相机来摆，可以被 3D 物体遮挡，适合"界面背后还能看到场景"；
③ World Space：把画布当 3D 物体摆进世界，可以旋转缩放、会被远近影响 —— 做头顶血条、VR 面板。
不能改 X/Y 是因为 Canvas 的尺寸由屏幕或相机决定（Rect Transform 的宽高由锚点和父容器算出来），你改的是它相对父级的位置，而根画布的父级就是屏幕。

2 分自适应三件套：
① 锚点 Anchor：控件相对父容器四角的定位，屏幕变宽时锚在右边的东西跟着走；
② 中心点 Pivot：控件自身旋转/缩放的基准点（蓝色圆圈），决定"从哪儿长"；
③ Canvas Scaler：把缩放模式设为 Scale With Screen Size 并给一个参考分辨率，界面按比例整体缩放。
（另有 Preserve Aspect 保持图片比例，防止图标被拉扁。）

2 分声音：
① Audio Listener（"耳朵"）挂在相机上，一个场景只能有一个，多了会报错；
② 格式：背景音乐用 mp3 / ogg（长、压缩比高），短音效用 wav / aiff（短、要立刻响应）；
③ 配置：背景音乐一个 AudioSource（勾 loop，用 Play()），音效另一个 AudioSource 用 PlayOneShot()——它能叠加，连点按钮不会把上一个音掐掉。
（Load Type 也可说：短音效用 Decompress on load，长音乐用 Compressed in memory 或 Streaming 省内存。）

第 8 题（10 分 · 2 小问）· 一局三分钟的关卡节奏

你要做一个「一局 3 分钟」的闯关小游戏，目标是让人第一局就想再来一局。

（1）（5 分）把这 3 分钟分成 4 个阶段，写出每个阶段给玩家的新东西（新机关/新敌人/新道具/新节奏）。

（2）（5 分）难度怎么涨？举 3 个可调数值，说明调哪个、往哪调、玩家会感受到什么。

参考答案游戏设计 · 可迁移自课设《虚数星区》的波次设计

5 分四段节奏（关键在于「每段都有新东西」，不能只是怪变多）：
① 0~30s 教学段：只放一种最基础的障碍，玩家走一遍就懂规则，给一次"我也能做到"的成就感；
② 30~90s 变化段：加第二个变量（比如移动平台 / 会追的敌人），逼玩家把刚学的规则组合使用；
③ 90~150s 压力段：数值上强度（速度更快、间隔更短），但不加新机制——让玩家感到"我变强了"而不是"游戏变难了"；
④ 150~180s 收尾段：一个小高潮（一小波连续障碍 / 一个迷你 Boss），最后给明确终点 + 结算。
加分点：每段开头给 1 秒"喘息"（音乐变化 / 镜头拉一下），让节奏有起伏，不是一路平推。

5 分三个可调数值（每个都要说"感受"）：
① 障碍间距：缩短 → 容错时间变少，玩家感到"要更专注、手更忙"；
② 移动速度：提高 → 同样的操作在新手眼里变难，感到"反应不过来"（最敏感，要小步调）；
③ 障碍出现频率/数量：提高 → 屏幕更热闹，感到"压迫感"；
（还可说：判定窗口变窄、可收集物变少。）
关键思路：一次只动一个数值，动了以后要观察玩家是"失误多了"还是"烦了"——前者是难度合适，后者是体验坏了。

第 9 题（15 分 · 3 小问）· 设计一款塔防

（1）（5 分）写出核心循环（玩家一分钟里重复做什么），以及「什么算通过、什么算失败」。

（2）（5 分）金币从哪来、花到哪去？怎么设计才不让玩家"一直攒着不用"？

（3）（5 分）第一关怎么教玩家？把教学拆成 3 步，每步只教一件事，并说明"玩家做错了会怎样"。

参考答案游戏设计 · 核心循环 / 经济 / 教学

5 分核心循环：
「看敌人从哪条路来 → 决定在哪造什么塔 → 收金币 → 升级或补塔 → 撑过这一波」，每 20~30 秒一波，波与波之间是决策时间，波中是观察时间。
通过：守住 N 波，基地血量 > 0；失败：怪物漏过去把基地血量扣到 0。
（好的循环要"决策→看到结果→马上能改"，间隔太长玩家就困了。）

5 分经济设计：
来源：击杀敌人给金币 + 每波结算奖励 + 卖塔回收一部分；
去处：造新塔、升级塔（攻击力/范围/攻速）、修基地；
防止"只攒不花"的三招：
① 利息上限或"金币不产生收益"——攒着没有额外好处；
② 波次压力递增——不花就打不过下一波（用难度逼消费）；
③ 限时折扣 / 前几波造价低——早投资早受益，制造"现在花更划算"的判断。
（本质：让"花钱"成为唯一解，而不是可选操作。）

5 分三步教学（每步只教一件事，且用「做错也死不了」的安全环境）：
① 教"造塔"：只留一条路、一个塔位，系统提示"点这里造塔"，敌人很弱——不造也打不死你，但会漏怪扣 1 血，让玩家自己发现"必须造"；
② 教"塔的类型有区别"：来一波"快速小怪"，提示换成攻速快的塔；如果玩家不换，怪会跑得很快（但血量仍低），失败信息写成"这波怪太快了，试试箭塔"；
③ 教"升级比多造更划算"：给一个只有 1 个塔位、但金币够升 3 级的地图，玩家升完发现能过——用一局让他自己得出结论。
关键：教学不要用大段文字，用关卡结构和失败提示教。

第 10 题（15 分 · 3 小问）· 三人小组怎么配合

你和两个同学做课设：一个管美术、一个管界面和材料、你写代码。

（1）（5 分）三个人各自交什么、在哪一步交接？写出你的交接顺序（谁先给谁什么）。

（2）（5 分）程序怎么把数值交给策划/美术去调，而不用改代码？（说出至少两种做法和区别）

（3）（5 分）提交前你要检查哪几项性能？每项说明"看什么指标、超了怎么办"。

参考答案工程协作 · 可迁移自课设《虚数星区》的四层结构与 SO 配置

5 分分工与交接顺序：
① 策划（你兼）→ 美术：先给需求文档（尺寸、风格、要几张、命名规则），美术按尺寸交付；
② 美术 → 程序：交 模型/贴图/切好的 UI 图，并且按约定命名（如 ui_btn_start.png、enemy_seeker.png），程序才不用猜；
③ 界面同学 ↔ 程序：界面同学出布局稿（每个按钮多大、放哪），程序按稿搭 Canvas；界面同学再回来验收真机效果；
④ 程序 → 全体：打包一版可玩 Demo，大家同一版本上提问题（不要各自改各自的副本）。
关键：每次交接都要有明确的产物 + 命名规范 + 版本号，否则最后合并会打成一团。

5 分把数值交出去：
① public 字段 + Inspector：变量改成 public float speed = 5f;，在 Inspector 里直接拖滑杆改，运行时也能改；缺点是改完关掉就丢，多点几次就乱了。
② ScriptableObject（配置资源）：把一组数值做成 .asset 文件（如敌人血量、子弹速度、波次表），策划改文件、程序读文件；能存档、能版本管理、能一处改全局生效。
③ 外部表格（CSV/JSON）：适合数值量大、要反复调的（关卡表），程序写个读表工具。
区别一句话：Inspector 适合"临时试手感"，SO 适合"定下来的配置"，表格适合"大批量数据"。给别人的东西一律用 SO，别让策划进代码。

5 分提交前的性能检查：
① Draw Call / Batches（Statistics 或 Frame Debugger）：超过几百就查——合图集、同材质合并、关掉不必要的实时阴影；
② 粒子数量与 Overdraw：同屏粒子太多会糊成一片还掉帧——限制同屏发射器数量、降 Start Lifetime、关掉不必要的光照；
③ GC Alloc（每帧内存分配）：Profiler 里看 GC 那行，每帧都分配就会周期性卡顿——把 new、字符串拼接、GetComponent 挪出 Update，用对象池；
④ 贴图尺寸 / 内存：小图标用 512 就够，别全用 2048；确认压缩格式（Android/iOS 各一套）；
⑤ 帧率与发热：真机跑 5 分钟看是否掉帧，锁 60 帧比放任它跑满更稳。

建议时间：案例 40 分钟 / 编程选择 30 分钟 / 综合设计 45 分钟 / 检查 5 分钟答题完毕请检查每一问是否都写了"为什么"满分 100 分
与第一、二套的区别：案例题换了全部考点——第 1 题考材质与贴图（法线/凹凸/高光 + Texture·材质·Shader 三层），第 2 题考地形与灯光烘焙，第 3 题考刚体参数 + 触发三条件 + FixedUpdate，第 4 题考粒子五模块 + over Lifetime 与 by Speed，第 5 题考Canvas 三种渲染模式 + 锚点 + 音频。编程选择题 15 个空仍然全部来自实验真代码，但换成了另外 15 个 API（Random.Range / List·Count·RemoveAt / GetKeyUp / SetActive / tag / GetAxis / AddForce / Sleep / Resources / PlayOneShot / SetBool / Vector3.forward / Rotate），与前两套不重复。综合设计题从「状态机 / 对象池 / 跑酷」换成「关卡节奏 / 塔防经济 / 团队协作与性能」，更贴老师说的「考设计能力」。
