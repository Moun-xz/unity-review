第 1 题（6 分）· 你是负责相机的程序第 2、5 章

项目做一个第三人称游戏。你接到的要求是：相机跟在角色身后，转弯不能晕、上下坡不能钻进地里、贴着墙时不能穿到墙外面去。

  1. 相机的偏移（offset）怎么算？为什么在 Start 里算一次就够，而不是每帧都算？
  2. 要做到「转弯不晕」，跟随与转向分别用哪个函数？靠什么参数控制「跟手还是飘」？
  3. 相机穿墙该怎么避免？（说出你用的手段和它依赖的技术）
参考答案第 2 章 · 数学基础｜第 5 章 · 物理与碰撞

① 偏移的算法。先在 Start 里记下 offset = 相机初始位置 − 目标位置，之后每帧只需 相机位置 = 目标位置 + offset。之所以只算一次，是因为 offset 描述的是「相机相对角色站在哪」，只要相对关系不变它就是个常量；每帧重算等于把上一帧的误差也带进来，误差会一点点累积，跑久了相机会慢慢飘走。这里用的是向量减法，得到的是一个方向与距离都确定的向量。

② 转弯不晕。位置跟随用 Vector3.Lerp(当前位置, 目标位置 + offset, Time.deltaTime * smooth)，让相机「慢慢追上去」而不是死贴着；朝向跟随用 Quaternion.Slerp，因为四元数的球面插值能保证旋转角速度均匀，不会像欧拉角那样在跨过 0°/360° 时突然翻转。smooth 这个参数就是手感旋钮：调大跟手、但转向生硬；调小柔和、但会拖尾。另外跟随放在 LateUpdate 里——所有 Update 中角色先移动，相机再算位置，同帧就能对上，不会出现「角色已经走了相机还留在上一帧」的一帧延迟。

③ 防穿墙。从相机位置向角色位置发一条射线（Physics.Raycast 加 LayerMask 只检测场景层），如果命中的距离小于相机到角色的距离，就把相机拉近到碰撞点再往前留一点的位置，让它贴着墙面而不是穿出去。依赖的是第 5 章的射线检测——射线检测只看「有没有碰到、碰到哪」，不产生物理反作用，所以不会把相机弹飞。现成的做法也可以用 Cinemachine 的 Collider 扩展组件，思路完全一样。

还能补一句加分：把鼠标的纵向输入用 Mathf.Clamp 限制在 −30°~60°，防止镜头翻到角色头顶或钻到脚下。

第 2 题（6 分）· 你是UI 美术第 4、8 章

界面要在 1080p 和 2K 两种分辨率下都清晰。其中有一个按钮，策划要求「高度固定，宽度随文字长度变化，但圆角和边框不能被拉变形」。你手上只有一张 256×64 的按钮图。

  1. 这张按钮图要怎么处理才能「只拉中间、不动四角」？
  2. 图标类资源在 2K 屏上发糊，从贴图本身找原因，可能有哪些？
  3. 美术交给程序的图，尺寸和 PPU 之间有什么关系？为什么这个关系必须在交付前定好？
参考答案第 4 章 · 材质与贴图｜第 8 章 · UGUI

① 九宫格（Sprite Border）。在 Sprite Editor 里给这张图设 Border——上下左右各切出一圈「不许拉伸」的边，中间留一块可拉伸区域。UI 里把 Image 的 Image Type 设成 Sliced，引擎就只拉伸中间那块，四个圆角和边框原样保留。切成九块之后，按钮拉多宽都不会变形，这是 UI 资源最标准的交付方式。如果按钮要跟随文字长度自适应，再给 Image 挂 Content Size Fitter 或让父级用 Layout Group 控制宽度。

② 图标发糊的三个来源。第一是原始尺寸不够——图本身只有 64×64，放到 2K 屏上放大两三倍必然糊，这没救，只能重出资源；第二是Mipmap 不该开的开了——UI 图标几乎总是固定屏幕尺寸显示，不需要缩小采样，勾了 Mipmap 反而多占 33% 内存、还可能采样到模糊的小层级，UI 图建议关掉 Mipmap；第三是压缩格式——默认的压缩对有锐利边缘的图标会产生块状噪点，UI 图标一般改用高质量压缩或干脆不压缩（代价是内存）。另外 Filter Mode 设成 Point（无滤波）可以保住像素风的硬边，设成 Bilinear 会糊。

③ 尺寸与 PPU。PPU（Pixels Per Unit）表示「多少像素算一个 Unity 单位」。一张图的世界尺寸 = 像素尺寸 ÷ PPU，所以图片换分辨率时，如果 PPU 不跟着改，它在世界里的实际大小就变了——同一张图原来 256px 占 2.56 单位，换成 512px 还按 100 PPU 就变成 5.12 单位，直接大一倍。对 UI 来说这个关系尤其要写死：UI 的尺寸是跟 Canvas 走的，交付前必须约定好「这张图在 1080p 下设计尺寸是多少像素」，程序按这个建 RectTransform，才不会出现「换台机器按钮突然变大」。我们的约定是：导入的 png 一律 100 PPU，UI 元素按 1080p 像素尺寸直接设宽高。

第 3 题（6 分）· 你是关卡美术第 3 章

要做一条「黄昏的海边山道」：有起伏的 地形、坡上的树林和草、低角度的落日、远处带雾，还要在路边立几盏路灯。

  1. 地形用什么工具做？「一片坡地」最快的做法是什么？
  2. 落日的光怎么打？（说出光源类型和至少三个要调的参数）
  3. 树林和草怎么放才不卡？路灯的光和落日的光，在渲染方式上有什么区别？
参考答案第 3 章 · 场景、地形与光照

① 地形。用 Unity 的 Terrain 系统（需先导入 Environment 资源包）。画一片起伏最快的做法是用 Set Height（Flatten）——先把整块地形抬到某个高度刷平，再用 Raise/Lower 局部堆出山脊；也可以用 Paint Texture + Create Layer 叠加草地、沙地、岩石几层贴图，让地表材质有变化。地形贴图是按图层混合的，不是一张大图铺满，所以同一个地形上能同时出现沙滩和草坡。

② 落日的光。用 Directional Light（平行光）——它模拟的是太阳这种「无限远」光源，光线平行、没有衰减、位置在哪都一样，只有旋转角度有意义。要调的参数：Rotation（压低到接近地平线，比如 X 轴 10°~15°）、Color（偏橙红而不是纯白）、Intensity（黄昏要比正午低）、Shadow Type（开软阴影，硬阴影在低角度下会有明显的锯齿条带）。如果场景是烘焙的，还要走一遍 Window → Rendering → Lighting，把 Color Space 设成 Linear，再 Bake 出 Lightmap。

③ 树草与两种光。树林和草不要一个一个摆——用 Terrain 的 Paint Trees / Paint Details 刷上去，引擎会自动做距离剔除（远处的树换成 Billboard 或直接不画）和细节密度控制，这是不卡的关键；草尤其要用 Detail 而不是实体模型，几千棵实体草会把 Draw Call 打爆。光方面：落日是实时平行光（Directional 每帧参与光照计算，动态物体也能被照到）；路灯如果场景是静态的，优先烘焙成 Lightmap，把光照「画」进贴图里，运行时零开销——但要注意 Point Light 的 Range 和 Intensity 必须调准，范围一大烘焙时间会暴涨。动态物体走不到烘焙光，需要额外放 Light Probe（光照探针）让它们也能被环境光影响。雾则在 Lighting 面板的 Other Settings 里开 Fog，调颜色和密度，让远处山道自然融进天色。

第 4 题（6 分）· 你是特效与动画第 6、7 章

角色被击中时要同时表现三件事：身上冒一股烟、身体向后仰一下、整个人闪一下红光。这段表现一局里会触发几十次。

  1. 「冒烟」用粒子做，说出你必须调的至少四个模块，以及烟气为什么会「慢慢变淡、越飘越散」。
  2. 受击动画用 Trigger 还是 Bool 参数？为什么？
  3. 一局要触发几十次，粒子系统怎么处理才不卡？
参考答案第 6 章 · 粒子系统｜第 7 章 · 动画系统

① 四个模块。Emission（喷多少、喷多快，设 Rate over Time 或 Burst 一次性喷一簇）、Shape（从哪喷、往哪个方向散，用 Cone 或 Sphere 让烟有体积）、Color over Lifetime（颜色随寿命变化）、Size over Lifetime（尺寸随寿命变化）。烟「越飘越散、慢慢变淡」正是这两个 over Lifetime 模块在起作用：Size over Lifetime 从小放大，粒子越来越多、越来越大，看起来就散开了；Color over Lifetime 的 alpha 从 1 渐到 0，就是淡出。再加 Velocity over Lifetime 给一点向上飘的速度，烟就有了「往上升」的动势。这套「over Lifetime」曲线描述的是单个粒子的一生——像花开花落，从生到死怎么变；而 by Speed 那类描述的是「运动快慢不同带来的差异」，像跑龙套的配角，不是这里要的。

② 用 Trigger。Trigger 是一次性的：调用 SetTrigger 后动画机立刻切到受击状态，播完自动清掉，下一次受击再设一次就行。Bool 是持续状态，设成 true 之后会一直保持，必须有人显式设回 false，否则第二次受击不会有反应——连续被打时尤其容易卡在受击动作里出不来。判据是「这个动作有没有持续时间」：受击、跳跃、攻击这种一瞬的动作都用 Trigger；「是否在跑」「是否在地面」这种持续状态用 Bool。

③ 别频繁创建销毁。粒子系统本身是复用的——把整个特效做成一个 Prefab，放进对象池，每次受击只是从池里取一个、Play() 一下、播完还回去。同时在粒子系统的 Stop Action 里设成 Callback 或 Destroy，让它播完自己回收；Max Particles 要设上限（比如 50），否则连续受击时粒子数会堆到几千，直接掉帧。闪红光不需要粒子，最简单的是把角色的 SpriteRenderer 的 color 短暂改成红色再 Lerp 回去，用协程控时长，比做一套粒子便宜得多。后仰动作交给动画机，和粒子、闪红通过同一个受击事件同时触发，三件事就对齐了。

第 5 题（6 分）· 你是主程序第 1、3 章

四个实验做完了，现在要把它们串成一个完整的小游戏交付：有菜单、有音效、有暂停。组里另外两个人不知道怎么组织工程，来问你。

  1. Unity 工程的目录怎么分？说出你会在 Assets 下建哪几个文件夹、各自放什么。
  2. Awake、Start、Update、FixedUpdate、LateUpdate 各自该放什么代码？
  3. 音效怎么管？为什么场景里只有一个 Audio Listener，它挂在哪？背景音乐和音效在 Load Type 上该选什么？
参考答案第 1 章 · 概述与工程组织｜第 3 章 · 音频

① 目录。Assets 下按类型 + 用途分：Scenes（场景文件）、Scripts（再按功能分子目录，如 Player / Enemy / UI / Core）、Prefabs（预制体）、Art（贴图、精灵、材质）、Audio（音乐与音效）、Resources（需要运行时按名字动态加载的资源）、Settings 或 Data（ScriptableObject 配置）。分目录的意义是让引用关系可预期：谁该引用谁一眼能看出来，不会出现「脚本里藏着一张不知道从哪来的图」。另外 Resources 要慎用——里面的资源会被无条件打进包体，越大加载越慢。

② 生命周期。Awake 最早，用来取引用、初始化自己（GetComponent、建对象池），此时别的对象可能还没准备好；Start 在第一帧 Update 前执行一次，用来读别人的数据、算初始值（比如算相机 offset），这时所有对象的 Awake 都完成了；Update 每帧一次、间隔不固定，放输入、UI 动效、计时；FixedUpdate 按固定步长调用，放所有物理相关代码（AddForce、改 velocity），因为物理引擎按固定步长解算，写在 Update 里每帧力度会随帧率变化；LateUpdate 在所有 Update 之后，放相机跟随，保证角色先动、相机后跟。

③ 音频。Audio Listener 挂在主相机上，一个场景只能有一个——它代表「耳朵的位置」，多了引擎会警告并且声音会重复播放。音源 AudioSource 可以有很多个，挂在发声的物体上（或用一个常驻的专门播音效）。Load Type 的选择：背景音乐这种长音频选 Streaming（边播边读，不占内存，代价是占一点 CPU）；短音效选 Decompress on load（加载时解压进内存，播放零延迟，适合频繁触发的小文件）；Compressed in memory 用在「文件不小、又要频繁播」的中间情况。文件格式上，长背景音乐用 mp3/ogg（压缩率高），短音效用 wav/aiff（无损、解码快）。音效播放用 PlayOneShot 而不是 Play——前者可以叠加，连续开枪不会互相打断。

第 6 题（7 空，14 分）· 贪吃蛇：边界限制与身体增长实验一

下面的脚本挂在蛇头上。功能是：方向键控制移动，出界时贴住边界不许跑出去，吃到食物时身体加一节。

public class SnakeHead : MonoBehaviour
{
    public float speed = 5f;
    public GameObject bodyPrefab;
    public List<Transform> body = new List<Transform>();
    private Vector2 dir = Vector2.right;
    private int score = 0;

    void Update()
    {
        if (Input.(7)(KeyCode.W)) dir = (6);
        if (Input.(7)(KeyCode.S)) dir = Vector2.down;

        transform.Translate(dir * speed * Time.deltaTime);

        // 出界就贴边，不许跑出屏幕
        float x = (1)(transform.position.x, -8.5f, 8.5f);
        float y = (1)(transform.position.y, -4.5f, 4.5f);
        transform.position = new Vector2(x, y);
    }

    void OnTriggerEnter2D(Collider2D other)
    {
        if (other.(2)("Food"))
        {
            Destroy(other.gameObject);
            score += 10;

            GameObject seg = (3)(bodyPrefab, transform.position, Quaternion.identity);
            body.(4)(seg.transform);
            MoveBody();
        }
    }

    void MoveBody()
    {
        Vector3 prev = transform.position;
        (5) (Transform seg in body)
        {
            Vector3 tmp = seg.position;
            seg.position = prev;
            prev = tmp;
        }
    }
}

G foreach　H for　I Vector2.up　J Vector3.up　K GetKeyDown　L GetKeyUp
参考答案
空答案为什么
(1)AMathf.Clamp(值, 最小, 最大) 把值夹在区间内。x 和 y 两处都要用它，两处必须填同一个答案。写 Mathf.Lerp（B）是插值，不会把越界的值拉回来，蛇照样跑出屏幕。
(2)CCompareTag("Food") 是老师实验里的写法，比 other.tag == "Food" 快且不会因标签不存在而抛异常。other 是 Collider2D，它没有 tag 之外的问题，但直连 .tag 比较在生产代码里不推荐。
(3)DInstantiate(预制体, 位置, 旋转) 生成身体节。Quaternion.identity 表示不旋转。注意是「以预制体为模板生成实例」，不是实例化脚本。
(4)EList.Add() 往列表尾部追加。这里的 body 是 List<Transform> 类型，用 Add 而不是 Remove。
(5)Gforeach (Transform seg in body) 遍历集合。这里不需要索引，用 foreach 最直接；for（H）需要写 body[i] 和长度判断，虽然也能跑但不是这个写法。
(6)IVector2.up 即 (0, 1)，二维里向上。Vector3.up（J）是三维类型，赋给 Vector2 dir 虽然能隐式转换，但这是 2D 项目，规范上该用 Vector2。
(7)KInput.GetKeyDown：按下的那一帧返回 true。两处都填它。用 GetKeyUp（L）会在松手时才触发，方向键的手感会变成「松手才转弯」；用 GetKey 则每帧都返回 true，按住会一直触发。

这题的三个坑：① (1) 两处同号，只填对一处不给分；② (7) 也是两处同号；③ CompareTag 与 tag == 的区别、GetKeyDown 与 GetKeyUp 的区别，都是实验里老师反复提过的点。

第 7 题（8 空，16 分）· 赛车：平滑跟随与冲线结算实验二 + 实验四

第一段让相机平滑跟车；第二段处理冲线：停表、播动画、放音效、音效渐弱。

public class RaceCamera : MonoBehaviour
{
    public Transform target;
    public float smooth = 5f;
    private Vector3 offset;

    void Start()
    {
        offset = transform.position - target.position;
    }

    void LateUpdate()
    {
        Vector3 want = target.position + offset;
        // 不是死贴着，而是慢慢追上去
        transform.position = Vector3.(8)(transform.position, want, Time.deltaTime * smooth);
    }
}

public class RaceFlow : MonoBehaviour
{
    public Animator anim;
    public AudioSource bgm;
    public float total = 60f;
    private float left;
    private bool over = false;

    void Start() { left = total; }

    void Update()
    {
        if (over) return;
        left -= Time.deltaTime;
        if (left <= 0f)
        {
            (9) = 0f;          // 停表，画面定住
            return;
        }
    }

    void OnTriggerEnter2D(Collider2D other)
    {
        if (other.(10)("Finish") && !over)
        {
            over = true;
            anim.(11)("Rank", 1);   // 名次是整数参数
            bgm.(12)();
            bgm.(13) = 0.8f;
            (14)(FadeOut());
        }
    }

    IEnumerator FadeOut()
    {
        yield return new (15)(0.8f);
        bgm.Stop();
        anim.SetTrigger("Over");
    }
}

空答案为什么
(8)BVector3.Lerp(当前, 目标, t) 线性插值。第三个参数 Time.deltaTime * smooth 让插值比例跟帧率无关，结果就是「越靠近目标速度越慢」的平滑追尾。Slerp（A）是球面插值，用于旋转不是位置。
(9)CTime.timeScale = 0 把整个游戏的时间冻结（物理解算、动画、协程全停）。这是暂停/定格的正确做法，不能靠把速度设 0——那样别的物体还在动。注意：timeScale = 0 后 Time.deltaTime 也变成 0，所以 UI 动效必须用 unscaledDeltaTime。
(10)ECompareTag("Finish")，与第 6 题同一写法。
(11)FAnimator.SetInteger——注释已经提示「名次是整数参数」，参数类型必须和设置方法对上：Float 用 SetFloat（G），Trigger 用 SetTrigger，Bool 用 SetBool。类型写错编译不一定报错，但动画机压根不会响应。
(12)HAudioSource.Play() 从头播当前 AudioClip。这里背景音乐只该有一份在响，不需要叠加；PlayOneShot（I）适合短音效，用它播背景音乐会出现多份同时播放。
(13)JAudioSource.volume，0~1 的音量。bgm.volume = 0.8f 就是设到八成音量，后面 FadeOut 再一点点降下去。
(14)KStartCoroutine(协程名()) 启动协程。协程本身就是 IEnumerator 方法，只能通过它来跑。
(15)Lnew WaitForSeconds(0.8f) 让协程停 0.8 秒。协程里的等待必须 yield return 一个 YieldInstruction，直接写数字不行。坑：WaitForSeconds 受 timeScale 影响，如果冲线时先执行了 (9)，这个等待永远不会结束——所以真实项目里要用 WaitForSecondsRealtime。

这题埋了两个真实项目里的坑：① timeScale = 0 会让 WaitForSeconds 卡死、让 deltaTime 变 0，所以 UI 与音效的计时必须用 unscaled 系列；② Animator 参数类型必须与 Set 方法匹配。答对这两点，说明真的动手做过。

三、游戏综合设计题40 分 · 不写代码

本大题三题均取自课程设计的 20 个选题，考核的是「你会怎么设计」，不是「代码怎么写」。答题按 规则（玩什么）→ 机制（用什么实现）→ 数值（调多少） 三层展开，每小问 5 分。

第 8 题（10 分，2 小问）· 弹球打砖块课设 · 题目 16

策划要一款经典打砖块：底部挡板左右移动，顶部与两侧布砖，小球弹来弹去打碎砖块。体验要求是「球永远不减速、反弹手感干脆」，另外球掉出屏幕要扣一条命。

（1）（5 分）小球「永远不减速地弹」该怎么配？说明你要用哪些组件、把哪些参数设成什么值，以及为什么。
（2）（5 分）球掉出屏幕怎么判定并扣命？说明判定区域、触发方式，以及扣命后要做哪几件事。

参考要点5 分 = 说清 3 个以上有效点

（1）不减速反弹

  • 用 Physics Material 2D 控制弹性：把 Bounciness（弹性系数）设成 1.0，Friction（摩擦）设成 0。弹性 1.0 表示碰撞前后速度大小不变、方向按法线镜像，这是「永远不掉速」的核心。
  • Rigidbody2D 上关掉一切耗能项：Gravity Scale = 0（俯视视角不需要重力，否则球会往下掉）、Linear Drag = 0（线性阻力会让速度随时间衰减）、Angular Drag = 0（如果不需要旋转）。
  • Collision Detection 设为 Continuous：球速很快时离散检测会「穿模」，球直接把砖穿过去，表现为「球突然消失/卡住」。连续检测是花费性能换准确性的取舍。
  • 球不挂重力、只给初始速度：velocity 给一个确定方向，之后交给物理引擎，不要每帧手动改 velocity——手动改会和物理解算打架，出现抖动。
  • （加分）如果发现速度仍有微小衰减，可以在碰撞回调里把速度重新归一化到目标速度，这是保底手段，但属于「掩盖问题」，不如先把参数配对。

（2）掉球扣命

  • 判定区域：在屏幕底部下方放一个长方形的 BoxCollider2D，勾选 Is Trigger，不参与物理碰撞（球要能穿过去而不是被它挡住）。
  • 触发方式：球是 Rigidbody2D + Collider2D，区域是 Trigger——满足触发条件，在 OnTriggerEnter2D 里用 CompareTag("Ball") 确认碰到的是球（区域里可能还有其他物体）。
  • 扣命后要做三件事：① 生命值减一，更新 UI 上的生命图标；② 把球重置回挡板上方并清零速度，等待玩家点击重新发球——这里必须先清零速度或先 Sleep()，否则瞬移回起点后球还带着旧速度，会直接飞出屏幕；③ 播一次失败音效，若生命归零则切到结算。
  • 对象池视角：球如果允许多球（道具分裂），掉出去的球不要 Destroy，改成 SetActive(false) 回收进对象池，避免频繁实例化。

第 9 题（15 分，3 小问）· 奇幻风塔防课设 · 题目 4

要做一款塔防：敌人沿固定路线走向基地，玩家在路边的格子上建塔拦截，每波敌人更强，杀死敌人得金币、建塔花金币。

（1）（5 分）敌人怎么沿路径走？路径用什么存，走到终点后怎么办？
（2）（5 分）塔怎么发现并攻击范围内的敌人？说清判定方式、攻击节奏、子弹从哪来。
（3）（5 分）波次与金币怎么设计，才不至于「前两波随便过、第五波必崩」？

参考要点每小问 5 分

（1）路径移动

  • 用 Waypoint（路径点）数组存一串空物体的位置，敌人在 Start 里拿到这个数组和一个当前索引 index。
  • 每帧用 Vector3.MoveTowards(当前位置, 目标点, speed * Time.deltaTime) 往下一个点走——它保证速度恒定，不会像 Lerp 那样「快到了就变慢」。
  • 到达判定：判断当前位置与目标点的距离小于一个小阈值（如 0.05），就把 index++ 指向下一个点。走完最后一个点即到达基地，触发基地扣血然后把敌人回收。
  • 朝向：用 Quaternion.LookRotation 或直接按两点方向翻转 Sprite 的 X 轴，让敌人始终面朝前进方向。
  • （加分）路径点数组放在一个 `Path` 脚本里统一管理，敌人只引用路径而不自己存点，这样换关卡只改路径不动敌人逻辑。也可以用 NavMesh，但对固定路线来说 Waypoint 更轻、更可控。

（2）塔的攻击

  • 检测方式二选一：① Physics2D.OverlapCircle——每隔一小段时间以塔为圆心、攻击半径为半径做一次圆形检测，拿到范围内的碰撞体；② 给塔挂一个 半径 = 攻击距离的 Trigger 圆形碰撞体，敌人进入时记录、离开时移除。前者实现简单、不用维护列表；后者不会漏掉「一直待在范围内」的敌人，实时性更好。塔多的时候后者更省，因为不用反复调用检测。
  • 攻击节奏：用一个 cooldown 计时器，每帧累加 Time.deltaTime，超过 attackInterval 才能开火并清零。不能每帧都打，否则帧率越高伤害越高，游戏平衡直接崩掉。
  • 选目标：范围内可能有多个敌人，按「离基地最近」或「最靠前」优先，不能让塔随机乱打——玩家会感觉塔在浪费输出。
  • 子弹从对象池取：塔开火时从池里取一发子弹、设好起点与目标，飞行到位后造成伤害并回收。绝对不要每次 Instantiate + Destroy，几百发子弹会把 GC 拖爆。近战塔可以直接用「命中即结算」不做飞行体。

（3）波次与金币

  • 波次曲线：不要线性加数量，改成「数量缓增 + 强度陡增 + 类型轮换」——前 3 波只出慢速低血的小怪让玩家熟悉建塔，第 4 波开始混入高速怪（逼玩家补减速/范围塔），Boss 波之前给一次「喘息波」（怪少但金币多）。每波之间留 5~8 秒准备时间，玩家才有功夫卖塔重建。
  • 金币闭环：击杀返造价的一定比例（比如 60%），保证「卖塔重建」的损失可承受，玩家才敢试不同搭配；如果击杀不返钱，一次建错就废了，玩家会直接重开而不是想办法。
  • 给保底：每波结束发一笔固定工资，让「一个怪都没杀到」的玩家也能慢慢攒起来，不至于彻底卡死。这是难度曲线的下限保障。
  • 数值要能改：塔的射程、伤害、造价、敌人的血量速度全部放进 ScriptableObject，程序不动代码、策划自己就能调平衡。这是「可玩性靠调不靠写」的工程前提。
  • （加分）难度不是越高越好：让玩家在「多建便宜的」和「攒钱建一个强的」之间反复犹豫，这个犹豫本身就是乐趣。如果只有一种最优解，塔防就退化成等待。

第 10 题（15 分，3 小问）· 3D 横版跑酷课设 · 题目 5

要做一款 3D 横版跑酷：角色自动向前跑，玩家只控制跳跃、左右变道、滑铲；路上要随机出现障碍、金币和药水；右上角要有小地图。

（1）（5 分）随机地图怎么生成，才不会出现「必死组合」或者「一眼看出在重复」？
（2）（5 分）右上角的小地图怎么做？
（3）（5 分）三种药水（加速、无敌、磁铁）怎么实现，才不会互相打架、也不会永久生效？

参考要点每小问 5 分

（1）随机地图

  • 不要随机摆障碍，要随机拼「路块」：预先做好若干段固定长度的路块 Prefab（每段内部已经验证过可通过），生成时按顺序拼接。随机发生在「选哪一段」和「段内的道具分布」，不发生在「障碍能不能躲」。
  • 保证至少有一条可通过路径：每段路块设计时就要留出至少一条能靠「跳 / 滑 / 变道」通行的通道。纯随机坐标生成几乎一定会造出无解组合，玩家死一次就会卸载。
  • 难度递增：用一个随距离增长的参数控制障碍密度和路块难度等级，前 300 米只用简单路块，之后逐步解锁带连续障碍的段。玩家会感觉「越来越紧张」而不是「越玩越乱」。
  • 对象池复用：跑过的路块不要 Destroy，回收进池里再从前方取出重新拼。跑酷是无限长的，靠 Instantiate 会让内存一路上涨、后期必卡。
  • 避免重复感：同一段路块不要连续出现两次；再用环境（天空盒颜色、远景建筑）随距离变化，制造「跑远了」的错觉。视觉变化比逻辑变化便宜得多。

（2）小地图

  • 用副相机 + Render Texture：在场景里放第二台相机，位置在角色正上方往下看（俯视），把它渲染到的目标设成一张 Render Texture 资源。
  • UI 上放一个 RawImage，Texture 指向那张 Render Texture，摆在 Canvas 右上角。RawImage 而不是 Image，因为 Render Texture 是动态纹理，Image 走的是 Sprite 管线。
  • Culling Mask 只显示关键物体（角色、障碍、终点），把地面细节、粒子、UI 层屏蔽掉——小地图要的是「信息」不是「画面」，全画出来只会糊成一团。
  • 跟随：副相机每帧同步角色的 X/Z 位置但保持固定高度和俯角，或干脆用正交投影按固定比例缩放，这样地图不会因为角色速度快慢而变形。
  • （加分）副相机要关掉 Audio Listener，否则两个 Listener 会警告。

（3）三种药水

  • 统一成 buff 系统，不要把三种效果写成三段独立逻辑。每个 buff 记录：类型、剩余时间、强度。角色身上维护一个 buff 列表。
  • 计时用协程或倒计时字段：吃到药水时把 duration 设成比如 8 秒，每帧减 Time.deltaTime，归零就移除效果并恢复原值。不要用「记录一个结束时间再比较」以外的野路子，容易在暂停时错乱。
  • 三种效果各自的实现：加速 = 改角色的 moveSpeed 倍率；无敌 = 让受击判定直接 return（或切一个 Layer 让碰撞矩阵不检测）；磁铁 = 每帧把一定半径内的金币用 MoveTowards 吸向玩家。
  • 不打架的规则：同类药水刷新时间而不是叠加（再吃一个就重置到满时长，不叠加效果，否则连吃五个加速会飞出去）；不同类药水可以共存，用独立的计时字段；所有效果移除时必须恢复成原始值而不是乘除抵消——乘除两次会因为浮点误差慢慢漂移，正确做法是记下原值，结束时赋回去。
  • 给玩家反馈：UI 上显示剩余秒数和图标，最后 2 秒闪烁提示。没有反馈的 buff 玩家根本感知不到自己吃到了什么。
设计题得分原则：这 40 分里有 30 分考游戏设计能力，而不是技术细节。每小问按「规则（玩什么）→ 机制（怎么实现）→ 数值（调多少）」三层写，每层至少一句。技术名词写错扣不了多少分，字数不够、层次不清才是真扣分。
