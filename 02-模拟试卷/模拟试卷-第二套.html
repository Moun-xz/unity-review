第 1 题（6 分）· 你是美工第 1 章

策划给你一张角色的 2D 原画，要你把这个角色做到能在 Unity 里跑起来。你会怎么做？

  1. 按顺序写出从原画到「模型进引擎」要经过的环节（分 2D 原画和 3D 建模两个阶段）。
  2. 为什么要做高模和低模两套？两者之间的细节靠什么手段弥补？
参考答案课件 01 · slide 15~23

2 分2D 原画 4 步：线稿绘制 → 上色（加光影、增强立体感）→ 细节修饰（色彩/质感/细节符合整体美术风格）→ 审查（与策划、美术指导定稿）。

3 分3D 建模 9 步：原画分析（风格/比例/透视/材质要求）→ 粗模 → 中模（加细节提精度）→ 高模（雕刻细分曲面）→ 低模拓扑（控面数、布线合理、与高模拓扑匹配）→ UV 拆分 → 烘焙法线贴图 → 材质与纹理（基础色/细节纹理/法线）→ 渲染（调灯光和材质）。
（≥7 步给 3 分，5~6 步给 2 分，顺序乱扣 1 分）

1 分为什么两套：高模细节足但面数高、引擎实时渲染跑不动；低模能跑但没细节。用烘焙把高模细节转成法线贴图贴到低模上，兼顾画质与性能；UV 是前提，没 UV 贴不上也烤不出。

第 2 题（6 分）· 你是程序（赛车实验）第 3 章

要做一个赛车场景：导入一堆现成的建筑和街道模型，加上地形，还要能切换天空盒。

  1. 导入的模型默认没有碰撞体，为什么需要补上？怎么补？
  2. 给场景加天空盒有三种做法，分别写出来，并说明两种脚本做法的区别在哪。
参考答案课件 03 · Skybox 三种做法 / 实验二 第 4、5 步

2 分为什么补 Collider：导入的模型只有 Mesh Filter + Mesh Renderer（能看不能撞），要参与碰撞就必须给它加 Collider——形状按模型选 Box / Sphere / Capsule / Mesh。实验二里就是因为这点，模型看着有、车却直接穿过去。
（加分：如果它要动，还要加 Rigidbody；静态场景物只加 Collider 就够）

4 分天空盒三种做法（每种 1 分，区别 1 分）：
① 材质法：新建 Material → Shader → Skybox → 6 Sided → 分别设置 6 个方向的贴图 → 赋给相机；
② 脚本法 A：不能给相机加 Skybox 组件，直接换材质——此时材质必须放在 Resources 文件夹下，否则 Resources.Load 找不到；
③ 脚本法 B：必须给相机加 Skybox 组件，然后 GetComponent<Skybox>().material = 材质 赋值。
区别：②靠路径加载、材质必须进 Resources；③靠组件引用，材质可以放任意位置。这两种不要记混。

第 3 题（6 分）· 你是程序（台球实验）第 4、5 章

要做一款台球游戏：主球能受力滚动、能撞球、进洞后要回到起点；同时主球要能始终朝向某个目标，还要判断目标在它前方还是后方。

  1. 「始终朝向目标」和「判断前后」分别用哪个数学工具？写出关键调用。
  2. 主球和球洞分别要挂哪些组件、Tag 怎么设？台球的弹性靠什么调？
  3. 进洞后要把主球放回起点，改位置之前必须先做什么？不做会怎样？
参考答案课件 04（A13~A16）/ 课件 05 / 实验三

2 分① 始终朝向：Vector3 dir = target.position - transform.position;
transform.rotation = Quaternion.Slerp(transform.rotation, Quaternion.LookRotation(dir), Time.deltaTime * k);
② 判断前后用点乘：Vector3.Dot(transform.forward, dir.normalized) > 0 在前、< 0 在后；
判断左右用叉乘：Vector3.Cross(forward, dir).y 的符号，正为右、负为左。

2 分③ 组件与 Tag：主球 = Rigidbody + Collider + Tag Player；目标球 = Rigidbody + Collider + Tag TargetBall；球洞 = Collider + Tag Hole。
弹性靠物理材质 Physic Material：Bounciness（弹力）调高、Friction（摩擦）调低。

2 分④ 改位置之前必须先 rg.Sleep()。
不做的后果：速度还留着，瞬移回起点后球自己又滚出去（或者带着旧速度乱飞）。Sleep() 会清速度并冻结刚体状态，是重置位置的前置条件。
（加分：物理相关代码写在 FixedUpdate 里；AddForce 施力 velocity 直接改速度）

第 4 题（6 分）· 你是特效与动画第 6、7 章

给炮塔做开炮特效：要有火光一闪、火星飞散、烟慢慢扩散消失；角色要有站立、行走、奔跑三种动作并能平滑过渡，同一套动作还要给另一个角色用。

  1. 三种效果分别用粒子系统的哪些模块、怎么调？（写明模块名和关键参数）
  2. 角色的三种动作用什么做平滑过渡？有一个参数控制「走 / 跑」的临界点，它的取值是多少？
  3. 让另一个角色也能用这套动画，靠什么机制？对模型有什么要求？
参考答案课件 06 粒子模块 / 课件 07 融合树与 Avatar

2.5 分① 三种效果（每种约 0.8 分）：
火光：生命周期很短（0.1~0.2s）、Color over Lifetime 白→橙→透明、Size over Lifetime 先大后收、Renderer 用 Additive 发光；
火星：Shape 用 Cone 定向发射、Initial Speed 大、Gravity Modifier > 0 让火星下坠、Renderer 用 Stretched Billboard 拉出速度线；
烟：生命周期 1~2s、Size over Lifetime 放大、Color over Lifetime 不透明→透明、材质用 Alpha Blended。

2 分② 平滑过渡用融合树 BlendTree（2D 双参数：Speed 控走跑、Direction 控左右）。
临界点：walking 三个子节点的 Direction = −1 / 0 / 1；Motion 层 walking = 0、run = 0.8，参数是 Speed。代码里 anim.SetFloat("Speed", 0.5f) 是走、1f 是跑。
（加分：过渡也可以给状态之间设 transition duration 交叉淡化；参数类型 Float / Int / Bool / Trigger，Trigger 触发后自动归 false）

1.5 分③ 多角色共用动画 = Avatar + 动画重定向 Retargeting。
Avatar 的作用是把导入模型的骨骼结构翻译成 Mecanim 标准人形骨骼，有了这层翻译，同一套动画剪辑就能给不同模型用。
对模型的要求：T Pose；骨盆位置的骨骼关节是所有骨骼的父层级；至少 15 个骨骼；动画剪辑的 Rig 要设 Humanoid 并 Copy From Other Avatar。

第 5 题（6 分）· 你是UI 与声音第 8 章 + 声音

做一款 1920×1080 的手机游戏界面：要能在不同分辨率下正常显示，按钮要能点，金币和血量要能实时刷新；背景音乐要一直循环，开炮、吃道具的音效要能同时响。

  1. 界面用到哪些技术？（从画布、布局、控件、交互四层说）
  2. 背景音乐和音效分别怎么配？两个 AudioSource 还是一个？用哪个播放方法？
参考答案课件 08 / 课件 05 音频 / 实验二、三 的 AudioSource

4 分① 界面四层（每层 1 分）：
画布层：Canvas + CanvasScaler（Scale With Screen Size，参考 1920×1080，Match 0.5）；Render Mode 常用 Screen Space - Overlay（一直在最前、自适应分辨率），要为 UI 加粒子特效时用 Screen Space - Camera（游戏相机 depth = −1、UI 相机 depth = 0）；
布局层：所有 UI 必须用 RectTransform；Anchors 锚点决定分辨率变化时贴哪——四角元素锚到对应角，底栏锚定底部并横向拉伸；Pivot 轴心是旋转缩放的基准；
控件层：Text/Button/Image（只能显示一个精灵，ImageType 用 Sliced 九宫格做底板拉伸不变形）/RawImage（可显示任意纹理）；图标打图集 Atlas 减少 draw call；
交互层：Graphic Raycaster（自动挂在 Canvas 上）+ EventSystem，少了按钮就点不动；数值刷新由脚本订阅事件改 Text，不要 Find 找 UI。

2 分② 声音：两个 AudioSource 分开挂——一个专放 BGM（loop = true，用 Play()），一个专放音效（PlayOneShot(clip) 可叠加播放不打断）。
不能用 Play() 放音效：它会打断上一个音，连击时会吞音。
（加分：AudioSource 可以挂在管理器上做全局，也可以挂在每个物体上；Resources.Load("Sound/hit") as AudioClip 取音频）

第 8 题（10 分 · 2 小问）· 状态与对象管理

你的射击游戏要做成：主菜单 → 选关 → 战斗中 → 暂停 → 结算，战斗中同屏几百颗子弹。

（1）（5 分）列出需要哪些状态，以及状态之间怎么切换、由谁触发。

（2）（5 分）子弹不用 Instantiate / Destroy，改用对象池。写出一个子弹从取出到回收的全过程，并说明为什么每次取出都要重置状态。

参考答案

5 分（1）状态与切换：
状态：主菜单 Menu → 选关 LevelSelect → 战斗中 Playing → 暂停 Paused → 结算 Result（可加开场 Boot、关卡过渡 Transition）。
切换与触发者：
① Menu → LevelSelect：玩家点「开始」，UI 按钮回调；
② LevelSelect → Playing：选中关卡并确认，由选关面板传出关卡参数；
③ Playing → Paused：按 Esc 或窗口失焦；Paused → Playing：点「继续」；Paused → Menu：点「返回主菜单」；
④ Playing → Result：生命归零或波次打完，由逻辑层（血量 / 关卡进度）判定后发事件；
⑤ Result → Playing：点「再来一局」，重置数据；Result → Menu/LevelSelect：返回。
要点：状态切换只在一处统一处理（一个 GameState 脚本），其他脚本只发事件，不各自改状态——否则会出现「暂停了子弹还在飞」。

5 分（2）对象池全过程：
① 预热：开局先 Instantiate 一批子弹，全部 SetActive(false) 放进池；
② 取出：找一个未激活的，SetActive(true) 并调 OnSpawn() 重置；
③ 使用：设位置、速度、伤害，进入正常飞行逻辑；
④ 回收：命中或超时后不 Destroy，先 OnDespawn() 清理，再 SetActive(false) 放回池；
⑤ 兜底：池空时扩容或复用最老的一个，不能返回 null。
为什么必须重置：池对象的「构造」只发生一次，第二次取出来时它还带着上次的速度、位置、计时器、粒子、事件订阅。
必须重置的四项：位置与旋转 / 速度与受力 / 生命值与状态 / 计时器与协程（加分：粒子 Stop() + Clear()、事件取消订阅）。

第 9 题（15 分 · 3 小问）· 设计一款跑酷游戏

（1）（5 分）写出核心循环（玩家在一分钟里重复做什么），并说明「什么条件算通过、什么条件算失败」。

（2）（5 分）障碍随机生成时怎么保证「一定过得去」？写出你的判定规则和生成顺序。

（3）（5 分）难度怎么递增？举 3 个可调数值，说明调哪个、往哪调、玩家会感受到什么变化。

参考答案

5 分（1）核心循环：观察前方 → 跳 / 滑 / 左右换道 → 吃金币和道具 → 速度自动加快 → 撞到障碍结算。
通过：跑完设定距离或达成目标分数；失败：撞到障碍（一次或几次，看设计）/ 掉落 / 超时。
成败判定写在哪：碰撞用 OnTriggerEnter 判 Tag（Obstacle / Coin），距离用累计位移判定。

5 分（2）随机生成要保证可通过，规则：
① 分段生成：把赛道切成固定长度的「片段」，每次取一个预制好的片段（预制件里已经验证过可通过），而不是随机撒单个障碍；
② 难度带权重：片段按难度分档，随距离提高高档片段的抽取概率，但相邻两个片段不能同时是高难（设冷却）；
③ 留出反应距离：障碍出现位置距玩家至少 速度 × 反应时间（如 0.8s），速度越快提前越远；
④ 保证有路：三车道里至少留一条完全无障碍，且连续的障碍之间间距 ≥ 一次跳跃的距离。
生成顺序：先定片段 → 再定障碍通道 → 最后铺金币（金币要铺在"安全路径"上，起到引导作用）。

5 分（3）难度递增（每项 1.5 分）：
① 前进速度：从 8 提到 15，加速曲线用缓动而不是线性 → 玩家感到"越来越赶"；
② 障碍密度：单位距离的片段数从 1 个/100m 增到 1 个/60m → 操作间隔变短；
③ 障碍类型解锁：先只出地面障碍，再出空中障碍（要滑），最后出组合障碍（要跳+滑）→ 逐步增加操作种类；
（其他可接受：金币价值降低、道具刷新率降低、出现"必须二选一"的分叉路）

第 10 题（15 分 · 3 小问）· 声音与结算

（1）（5 分）游戏里至少有三类声音（背景音乐、打击音效、界面音）。分别说明它们的播放时机、能不能被打断、以及你用什么方法实现。

（2）（5 分）玩家要能在设置里分别调音乐和音效的音量，并且下次进游戏还是上次的值。说明怎么分轨、怎么保存。

（3）（5 分）结算界面要显示哪几项？数据从哪来？最高分怎么保证不丢？

建议时间：案例 40 分钟 / 编程选择 30 分钟 / 综合设计 45 分钟 / 检查 5 分钟答题完毕请检查空白处是否写满满分 100 分
参考答案

5 分（1）三类声音：
① 背景音乐 BGM：进关卡时开始，循环不断，不能被打断——用一个独立 AudioSource，loop = true，Play() 一次即可；切换场景时用 DontDestroyOnLoad 或由音频管理器统一接管；
② 打击音效：命中/爆炸/吃道具时播，必须能叠加——用 PlayOneShot(clip)（不会打断上一个音），连击时多个音同时响；
③ 界面音：点击按钮、开关面板时播，不循环、短促，同样用 PlayOneShot；
关键判断：Play() 会打断同一 AudioSource 上的上一个音，所以音效不能用 Play，否则连击时会"吞音"。

5 分（2）分轨调音量 + 保存：
① 分轨：两个 AudioSource 分别叫 Music 和 SFX；更规范的做法是用 AudioMixer 建 Music / SFX 两个 Group，各自的 AudioSource.outputAudioMixerGroup 指向对应 Group；
② 调节：AudioMixer.SetFloat("MusicVolume", Mathf.Log10(v) * 20)——音量是对数的，直接给 0~1 会很怪；也可简单用 audioSource.volume = v；
③ 保存：设置面板的 Slider 变化时 PlayerPrefs.SetFloat("musicVol", v)，关面板调 PlayerPrefs.Save()；进游戏时 GetFloat("musicVol", 1f) 读回来并应用到 Mixer；
④ UISlider 取值：slider.value（0~1）绑到音量，slider.onValueChanged.AddListener(...) 监听变化。

5 分（3）结算界面：
显示项：本局得分、击杀/收集数、最高连击、用时或距离、历史最高分（破纪录要给提示）。
数据来源：局内由逻辑层累加（击杀加分 × 连击倍率），结算时一次性汇总；界面只负责显示，不反向去场景里读数。
最高分不丢：PlayerPrefs.SetInt("bestScore", score) + Save()，并且只有超过旧值才写；读取用 GetInt(key, 0)。
（加分：结算面板要按状态机进 Result 才显示；分数滚动动画用 unscaled 时间，暂停时不卡）
