一、案例分析题30 分 · 每题 6 分

第 1 题（6 分）· 第 1 章 · 身份：美术

你刚进项目组做美术，主美给了你一张策划画的 2D 角色原画，要求你把这个角色做到能在 Unity 里跑起来。请回答：

  1. 按顺序写出从这张原画到「模型能进引擎」要经过的环节（分 2D 原画和 3D 建模两个阶段写）。
  2. 为什么要做高模和低模两套？两者之间的细节靠什么手段弥补？
参考答案

2 分2D 原画 4 步：线稿绘制 → 上色（加光影、增强立体感）→ 细节修饰（色彩/质感/细节符合整体美术风格）→ 审查（与策划、美术指导一起定稿）。

3 分3D 建模 9 步：原画分析（风格/比例/透视/材质要求）→ 搭粗模 → 中模（加细节提精度）→ 高模（雕刻细分曲面）→ 低模拓扑（面数控制、布线合理、与高模拓扑匹配）→ UV 拆分 → 烘焙法线贴图 → 材质与纹理制作（Substance Painter：基础色/细节纹理/法线）→ 渲染（调灯光和材质）。
（写到 7 步以上给 3 分，5~6 步给 2 分，顺序明显错乱扣 1 分）

1 分为什么两套：高模细节足但面数高，引擎实时渲染跑不动；低模面数低能跑但没细节。用烘焙把高模细节转成法线贴图贴到低模上，兼顾画质和性能。UV 要合理拆分才能烤得出来。

第 2 题（6 分）· 第 3 章 · 场景：资源加载失败

你把一张贴图放在 Assets/Textures/player.png，代码里写 Resources.Load("Textures/player") as Texture，运行时返回 null；同一份代码里 GameObject.Find("Player") 也返回 null，但场景里明明有一个叫 Player 的物体。

  1. 这两处 null 分别至少列出 3 个可能原因。
  2. 说出你的排查顺序（先查什么、后查什么）。
参考答案

3 分Resources.Load 返回 null 的三个原因（每个 1 分）：
① 路径必须相对于名为 Resources 的文件夹——你的图在 Assets/Textures/，不在 Assets/Resources/Textures/ 下，所以找不到；
② 路径不带扩展名（写 "Textures/player" 对，写 "Textures/player.png" 错）；
③ 大小写要和磁盘一致（Windows 不敏感、打包后敏感，编辑器里要先按严格写）；
（加分：贴图类型没设成 Texture / Sprite，或 as Texture 转换类型不匹配）

2 分GameObject.Find 返回 null 的三个原因：
① 目标物体在层级里没激活（SetActive(false) 的物体 Find 不到）；
② 名字不完全一致（多了空格、大小写不同、带了 "(1)" 后缀）；
③ 调用时机太早——在 Awake 里找还没被实例化出来的预制体；
（加分：它其实是预制体资源，不在场景里，必须 Instantiate 之后才存在）

1 分排查顺序：先确认路径/名字（肉眼比对磁盘目录与字符串）→ 再确认对象是否激活、是否已在场景→ 最后确认调用时机（把查找挪到 Start 或 OnEnable，打 Debug.Log 看返回值）。原则上优先用引用（Inspector 拖）而不是 Find。

第 3 题（6 分）· 第 4 章 · 场景：敌人朝向与方位判断

飞行射击游戏里，敌人需要：① 一直面向玩家；② 判断玩家在它前方还是后方；③ 判断玩家在它左侧还是右侧。

  1. 这三件事分别用哪个数学工具？写出关键调用。
  2. Quaternion.Slerp 和 Quaternion.RotateTowards 的第三个参数分别是什么含义？
  3. 如果要求转向不能瞬间完成、也不能转过头，你会怎么处理？
参考答案

2 分① 面向玩家：Vector3 dir = player.position - transform.position;
Quaternion target = Quaternion.LookRotation(dir);
transform.rotation = Quaternion.Slerp(transform.rotation, target, Time.deltaTime * k);

2 分② 前后用点乘：float d = Vector3.Dot(transform.forward, dir.normalized);　d > 0 在前方、d < 0 在后方、d ≈ 0 在侧面。
③ 左右用叉乘：Vector3 c = Vector3.Cross(transform.forward, dir);　看 c.y 的符号：c.y > 0 在右侧、c.y < 0 在左侧。
（写「叉乘得旋转轴，y 分量为正说明要绕 y 轴正向转」同样给分）

1 分第三参数区别：Slerp 的 t 是 0~1 的比例（插值进度）；RotateTowards 的第三参数是每帧最多转多少角度（度/秒 × deltaTime）。记混这两个是常见错。

1 分不瞬间也不转过头：Slerp 的 t 乘 Time.deltaTime 并钳制 ≤ 1；或直接用 RotateTowards 配合 Mathf.Min(rotationSpeed * Time.deltaTime, Quaternion.Angle(transform.rotation, target)) 限速；手写方案：Vector3 axis = Vector3.Cross(transform.forward, dir); 再 Quaternion.AngleAxis(speed * Time.deltaTime, axis)。

第 4 题（6 分）· 第 5 章 · 场景：台球游戏的三个怪现象

台球游戏做完后出现三个现象：

  1. 球滚到洞口边缘就被弹开，进不去；
  2. 球停下后再按方向键推不动，要重启才恢复；
  3. 球撞墙时抖动一下然后粘在墙里。

请分别说明原因和改法。

参考答案

2 分① 洞口边缘被弹开：球洞用的是实心碰撞体，球真的撞上去了。台球需要的是「进去」，不是「撞住」。
改法：把洞的 Collider 勾 Is Trigger（球穿过时用 OnTriggerEnter 判 tag），或者把洞口做成凹陷/低于桌面的几何形状；前提是球有 Rigidbody、至少一方有 Collider。

2 分② 停下后推不动：球的刚体进入了 Sleep（休眠）状态——静止一段时间后物理引擎让它休眠以省性能，此时外力不生效。老师代码里 rg.Sleep() 是主动让它休眠（重置位置前必须这么做），副作用就是"推不动"。
改法：施加力之前先 rg.WakeUp()；或调低 Rigidbody 的 Sleep Threshold；检查 Constraints 有没有把 Freeze Position 勾上。

2 分③ 抖动后粘在墙里：物理材质（Physic Material）参数不当 + 碰撞检测模式不够。
改法：墙和球的 Physic Material 把 Friction 调低、Bounciness 调低（不要给墙很高的弹性）；球速度较快时把 Collision Detection 改成 Continuous / Continuous Dynamic 防止穿透；Interpolate 设 Interpolate 减轻视觉抖动；移动统一写在 FixedUpdate 里。

第 5 题（6 分）· 第 7、8 章 · 场景：动画与界面各一个毛病

第 7 章：角色走路动画一播放，角色自己就往前漂移，和键盘控制打架。
第 8 章：界面在 1920×1080 下正常，拿到 1366×768 的笔记本上，底部按钮跑到屏幕外，按钮底图拉伸后发虚。

四个问题（动画 1 + 界面 3）分别说明原因和改法。

参考答案

1.5 分动画漂移：勾了 Apply Root Motion，动画自带的位移在推动角色，和控制代码打架。
改法：取消勾选，位移交给代码；或者保留 Root Motion 但不再用代码做位移，两者只能选一个。

1.5 分按钮跑到屏幕外：锚点（Anchors）用的是默认中心锚点，分辨率一变，元素按中心比例偏移就被挤出屏幕。
改法：底部按钮栏的锚点设成 Min/Max 都贴底（y = 0）并允许横向 Stretch；四角元素各自锚到对应的角；再配 CanvasScaler（Scale With Screen Size，参考分辨率 1920×1080，Match 0.5）。

1.5 分底图拉伸发虚：Image 的 ImageType 用了 Simple，整张图被拉变形，圆角被抻长、边线变模糊。
改法：改成 Sliced（九宫格切片），在 Sprite Editor 里设好 Border；如果是重复纹理用 Tiled。

1.5 分按钮点了没反应（题干第三问）：
① Canvas 上缺 Graphic Raycaster，或场景缺 EventSystem；
② 按钮的 Raycast Target 被关掉了；
③ 上面盖了一层全屏透明 Image 且它的 Raycast Target 还开着，把点击吃掉了——淡入/遮罩层一定要关 blocksRaycasts；
④ 按钮的 interactable = false。

第 8 题（10 分 · 2 小问）· 性能与对象池

你的射击游戏每一关要刷 200 个敌人和上千颗子弹，目前用 Instantiate 创建、Destroy 销毁，玩到后期会明显掉帧。

（1）（5 分）改用对象池后，一个子弹从「被取出」到「被回收」要经历哪几步？代码上主要改哪几个地方？

（2）（5 分）为什么池对象每次取出来都必须重置状态？请列举至少 4 个必须重置的项，并说明不重置会出什么问题。

参考答案

5 分（1）取用到回收的五步：
① 预热：开局先 Instantiate 一批对象全部 SetActive(false) 放进池子（不要边玩边创建）；
② 取出：从池里找一个未激活的，SetActive(true) 并调用 OnSpawn() 重置状态；
③ 使用：设置位置、速度、目标，进入正常逻辑循环；
④ 回收：命中/超时后不 Destroy，调 OnDespawn() 做清理再 SetActive(false) 放回池子；
⑤ 兜底：池空了要扩容或复用最老的一个，不能返回 null。
代码上改三处：把 Instantiate 换成 Pool.Get()、把 Destroy 换成 Pool.Release()、给对象加 IPoolable 接口并在 OnSpawn 里重置。
（说出「预热 + 取 + 回收 + 重置」四要素即给 4 分，提到池空兜底再给 1 分）

5 分（2）必须重置的四项（每项 1 分，第 5 项加分）：
① 位置与旋转——不重置会在上次死亡的地方冒出来；
② 速度 / 受力（Rigidbody）——不重置会带着旧速度飞，甚至 Sleep 状态残留；
③ 生命值 / 状态机——不重置会出现"一出来就是残血"或卡在死亡状态；
④ 计时器 / 协程 / Invoke——不重置会重复播放旧动画、旧音效，协程叠加；
⑤ 子物体与特效引用——血条、粒子、Render 材质要复位，粒子 Stop() 并 Clear()；
⑥ 事件订阅——不取消会重复注册，一次事件触发多次。
一句话总结：池对象的「构造」只发生一次，所以每次出生都必须把自己恢复成刚 new 出来的样子。

第 9 题（15 分 · 3 小问）· 设计一款三消游戏

（1）（5 分）写出这款游戏的核心循环（玩家在一分钟里重复做的那几件事），并说明「三个相同即可消除」这个判定要检查哪些方向、按什么顺序检查。

（2）（5 分）设计三种特殊元素（例如整行消除、范围爆炸、变色），分别写出它们的生成条件、触发条件和效果。

（3）（5 分）难度怎么递增？举出 3 个可调数值，说明调哪个、往哪个方向调，以及玩家会感受到什么变化。

参考答案

5 分（1）核心循环：观察棋盘 → 交换相邻两个元素 → 判定是否形成三连 → 成立则消除 → 下落 → 补充 → 连锁再判；不成立则交换回退并给提示。
判定顺序：只检查被交换的那两个格子所在的行和列（四个方向），不用全盘扫描；
① 先判横向：以该格为中心向左右扩展，累计同色数 ≥ 3；
② 再判纵向：向上下扩展；
③ 两者可同时成立（形成 L / T 形），要合并成一次消除而不是算两次；
④ 消除后下落 → 补新元素 → 递归再判，直到无三连（连锁 Combo）。

5 分（2）三种特殊元素（每种 1.5 分，写清「生成/触发/效果」三要素才满分）：
① 整行消除（火箭）：生成条件——四连（一行四个同色）；触发条件——被交换或被消除波及时；效果——清空整行（或整列）。
② 范围爆炸（炸弹）：生成条件——L 形 / T 形五连；触发——被消除时；效果——炸掉周围 3×3 九格。
③ 变色（彩球）：生成条件——五连成一线；触发——和任意元素交换时；效果——全场同色元素一起消除。
（说清「越难达成的组合 → 越强的效果」这条设计原则，加 0.5 分）

5 分（3）难度递增，三个数值（每个 1.5 分，写清「调什么/往哪调/玩家感受到什么」）：
① 可用步数（或时间上限）递减：每关从 30 步降到 22 步 → 玩家感到「每一步都要想」；
② 目标分 / 目标收集数递增：从 1000 分涨到 3000 分 → 需要更多连锁；
③ 元素种类数增加：从 5 种颜色加到 7 种 → 凑三连的概率下降、棋盘更"乱"；
（其他可接受的：初始障碍数量增加、特殊元素出现权重降低、掉落不均衡度提高）
设计要点：难度要「爬坡不跳崖」——一次只动一个数值，且给玩家一关"喘息关"。

第 10 题（15 分 · 3 小问）· 状态机与暂停

（1）（5 分）列出这款游戏需要哪些状态（至少 4 个），写出状态之间怎么切换、由谁触发。

（2）（5 分）按下暂停后，哪些东西必须停、哪些必须继续动？分别用什么手段实现？为什么不能一律停掉？

（3）（5 分）结算界面要显示哪几项数据？这些数据从哪来？怎么做才能保证「最高分」下次进游戏还在？

建议时间：案例 40 分钟 / 编程选择 30 分钟 / 综合设计 45 分钟 / 检查 5 分钟答题完毕请检查空白处是否写满满分 100 分
参考答案

5 分（1）状态与切换：
状态：主菜单 Menu → 游戏中 Playing → 暂停 Paused → 结算 Result（可加 开场 Boot、关卡过渡 Transition）。
切换与触发者：
① Menu → Playing：玩家点「开始」，由 UI 按钮回调通知状态机；
② Playing → Paused：玩家按 Esc 或失焦，由输入/窗口事件触发；
③ Paused → Playing：点「继续」；Paused → Menu：点「返回主菜单」；
④ Playing → Result：生命归零或波次打完，由逻辑层（血量/关卡）判定后发出事件；
⑤ Result → Playing：点「再来一局」（重载场景或重置数据）。
要点：状态切换只由一处统一处理（一个 GameState / 状态机脚本），其他脚本只发事件，不各自改状态。

5 分（2）暂停时什么停、什么继续：
必须停：角色移动、敌人 AI、子弹飞行、波次计时、物理模拟 → 用 Time.timeScale = 0 一行解决（所有受 timeScale 影响的 Update/FixedUpdate 与动画一起停）。
必须继续动：界面动画（面板淡入、按钮悬浮）、暂停图标呼吸、倒计时/计时显示之外的 UI 动效。
手段：这些地方全部用 Time.unscaledDeltaTime，不受 timeScale 影响；如果还要用实时时间做逻辑，必须自己判断 if (state == Paused) return;。
为什么不能一律停掉：timeScale = 0 会把 UI 动效一起冻住——面板停在淡入一半、按钮悬在半空，看起来像卡死；而且 timeScale = 0 时 FixedUpdate 完全不执行、Update 照常执行，物理和逻辑行为不一致。

5 分（3）结算界面：
显示项：本局得分、击杀数 / 连击数、存活时间、通过波次、历史最高分（新纪录要提示）。
数据来源：局内由游戏逻辑累加（击杀加分、连击倍率），结算时一次性汇总；不要从 UI 反读。
持久化：用 PlayerPrefs.SetInt("bestScore", score) + PlayerPrefs.Save()（跨关卡/重启都在），读取用 GetInt(key, 默认值)；比较后再写，只有超过才覆盖。
（也可答：存档文件 / ScriptableObject 做运行时配置但持久化仍要落到 PlayerPrefs 或磁盘）
