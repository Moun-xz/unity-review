一、美工的工作流程课件 01 · slide 15~23 ★最可能问

如果只让你背一样东西来应付「你是美工」这类题，就是这一段。老师课件里把美术资产制作拆成两个阶段、共 13 步。

阶段 1 · 2D 原画（4 步）

步骤课件原话 / 要点
(1) 线稿绘制用绘图软件绘制角色和场景的线稿，保证形体的准确、风格的规范
(2) 上色为线稿上色，添加光影效果，增强立体感和视觉冲击力
(3) 细节修饰对上色后的作品做细节完善，确保色彩、质感和细节符合游戏的整体美术风格
(4) 审查与策划和美术指导进行最终审查，确保原画符合项目要求与预期效果

阶段 2 · 3D 建模（9 步，这条链必须能背）

步骤课件原话 / 要点
(1) 原画分析分析 2D 原画，了解风格、确定模型比例、透视、体感的材质要求，为二次设计做准备
(2) 搭建粗模在 3D 软件中按原画搭出粗略形状，及时和 2D 原画组沟通更正需求
(3) 制作中模在粗模基础上增加细节、细化，达到更高精度
(4) 制作高模用雕刻软件细分曲面增加面数，做高精度雕刻，达到所需细节水平
(5) 低模拓扑按高模制作低多边形模型，用于引擎中的实时渲染。注意面数控制、布线合理性；高低模拓扑结构要匹配，才能有效烘焙
(6) UV 拆分对低模做 UV 拆分并合理排列，为法线烘焙做准备
(7) 烘焙法线贴图用烘焙技术把高模的细节转移到低模上，形成法线贴图
(8) 材质与纹理制作在 Substance Painter 等软件里制作基础颜色、细节纹理、法线贴图
(9) 渲染用渲染软件做最终渲染，调整灯光和材质达到最佳视觉效果
这道题的「加分句」在这一步——把「为什么」说出来，就不只是背步骤：
① 为什么要有高模+低模两套：高模好看但面数太高，引擎实时渲染跑不动；低模面数低能跑，但没细节。
② 烘焙的作用：把高模的细节「烤」进一张法线贴图，贴在低模上，用一张贴图换来接近高模的观感——画质和性能的折中。
③ UV 拆分是前提：没有合理的 UV，贴图就无法正确映射，法线也烤不出来。

二、渲染管线三选课件 01 ★选择题 + 案例都可能

管线适用范围（课件原话）
内置渲染管线
Built-in		默认渲染管线，适用于原型设计或对画质要求不高的游戏，适用于低端设备
通用渲染管线
URP		对平台支持广泛，性能表现较好，适合移动端、桌面端、网页端
高清渲染管线
HDRP		适合大型 3A 游戏，有高清渲染需求，适合桌面和主机项目
美工视角怎么答：选管线不是看哪个好看，是看目标平台 + 性能预算 + 画质要求三者。手机小游戏选 URP 或 Built-in；主机 3A 选 HDRP。

三、纹理 → 贴图 → 材质课件 04 ★美术的理论核心

这三个词老师课件里给了明确定义，且是层层包含的关系——年年都可能问「三者区别」。

概念课件原话
纹理
Texture		最基本的数据输入单位，游戏领域基本上都用位图；此外还有程序化生成的纹理（Procedural Texture）
贴图
Map		包含另一层含义是「映射」——把纹理通过 UV 坐标映射到 3D 物体表面。贴图除了纹理以外还包含UV 坐标、贴图输入输出控制等信息
材质
Material		是一个数据集，给渲染器提供数据和光照算法；贴图只是其中数据的一部分，按用途不同会被分成不同类型
一句话记法（能背下来就够答）：
纹理是原料（一张图）→ 通过 UV 映射贴到模型表面叫贴图 → 贴图 + 光照算法 + 参数打包成数据集叫材质 → 交给渲染器去画。

制作流程（课件原话，一句话）

软件建模 → 贴图表现基础颜色 → 使用材质表现「质感」 → 材质可以由 Shader 复杂编程

贴图的 7 种类型

类型用途
Texture（普通）基础颜色贴图
Normal Map（法线）记录表面凹凸朝向，让低模看起来有细节（就是第 7 步烤出来的那张）
GUI界面用贴图
Sprite 2D and UI2D 精灵 / UI 用
Cursor鼠标指针
Cookie灯光遮罩（做光斑、窗影）
Lightmap烘焙出来的光照贴图
Cubemap立方体贴图，类似 Skybox，模拟物体对环境的反射（六面）

三种特殊贴图（实验三考过）

名称要点
立方体贴图
Cubemap		六面贴图，用来模拟物体对环境的反射；创建方式 Legacy → Cubemap，材质 Shader 选 Legacy Shaders → Reflective → Diffuse，把 Cubemap 赋给 Reflection Cubemap 属性
视频贴图贴图内容是视频，可用于过关画面等
渲染贴图
Render Texture		贴图是动态的，内容由场景中的摄像机实时获取（实验三用它做多相机小地图，再用自发光材质显示在屏幕上）

网格三件套（问「模型怎么进引擎」就答这个）

组件课件原话 / 要点
Mesh Filter
网格过滤器		从资源中拿出网格并传递给网格渲染器用于屏幕渲染
Mesh Renderer
网格渲染器		负责绘制。若网格渲染器不存在，网格仍存在于场景中，但不能绘制。属性：Materials（材质列表）、Receive Shadows（接受阴影）、Light/Reflection Probe
Skinned Mesh
Renderer
蒙皮网格渲染器		导入网格资源时，如果是蒙皮的，Unity 自动创建它；不是则创建 Mesh Filter + Mesh Renderer

Shader（着色器）

  • 材质由着色器实现——换 Shader 就是换「质感算法」（金属 / 自发光 / 反射）
  • 定制使用着色语言 ShaderLab
  • 原理：ShaderLab（CG 的二次简化）调用 Direct3D 或 OpenGL 实现 GPU 控制
  • 课件里的实际用法：自发光 Legacy Shaders → Self Illumin → Diffuse；反射 Legacy Shaders → Reflective → Diffuse；天空盒 Skybox → 6 Sided

四、Skybox 与光照课件 03 ★实验二直接用

Skybox：屏幕上任何空的部分都显示它

课件定义：Skybox 是屏幕上任何空的部分将显示当前相机的天空盒；Background 是没有天空盒的情况下剩余屏幕的颜色。

做法步骤 / 坑
方法 1
材质		创建 Material → Shader → Skybox → 6 Sided → 分别设置 6 个方向的贴图 → 赋给相机
方法 2
脚本		脚本赋值，不能给相机加 Skybox 组件；此时材质必须放在 Resources 文件夹下，否则找不到
方法 3
脚本		必须给相机加 Skybox 组件，然后 GetComponent<Skybox>().material = ...
两种脚本做法的区别就是考点：不挂组件 → 材质必须进 Resources 用 Resources.Load 拿；挂了组件 → 可以直接 GetComponent<Skybox>().material 赋值。记混了就会答错。

光照与烘焙

  • 光照是模拟光的互动和反弹的算法；精确仿真光照代价高，所以游戏会预先处理一部分计算，而不是全部实时运算
  • 全局光照（GI）：带间接光源的光照
  • Area Light（区域光）：无法用作实时光照，一般用于光照贴图烘焙，必须烘焙、物体必须静态，用于建立柔和的照明效果
  • 烘焙路径：Window → Rendering → Lighting Settings → Baked Lightmap（课件写作 Backed，是拼写笔误）
美工视角的价值句：烘焙 = 把光照提前算好存进贴图（Lightmap），运行时不再算，用空间换性能；代价是物体必须静态、光不能动。

五、粒子系统（特效）课件 06 ★老师说会考

1:31 那句里老师单点了「粒子系统」。对美工来说粒子就是特效：爆炸、火花、烟尘、拖尾、升级光效。

模块 / 概念作用
Emission（发射）每秒发多少、什么时候发（Rate over Time / over Distance、Bursts 爆发）
Shape（形状）从什么形状发射：Sphere / Cone / Box / Circle，决定特效的方向感
Initial（初始）初始速度、大小、生命周期、旋转
Color over Lifetime随生命周期变色（火：橙→红→黑烟）
Size over Lifetime随生命周期变大/变小（烟扩散、火花收缩）
Renderer（渲染）Billboard / Stretched Billboard（拉伸，做速度线）/ Horizontal Billboard（地面光圈）/ Vertical Billboard / Mesh；材质选 Additive 做发光、Alpha Blended 做烟雾

课件里的四种颜色控制（也是代码考点 A21~A24）

做法API / 说明
随机双色MinMaxGradient（两个颜色之间随机）
渐变动态色Gradient（随生命周期按色带变化）
每颗粒子独立色开启 Per Particle Color，或用 SetCustomParticleData
粒子开启 / 关闭ParticleSystem.Play() / Stop() / Clear()；emission.enabled = false 只停发射不清场
美工答「怎么做爆炸特效」的五要素：发射形状（球形扩散）→ 生命周期（0.6~1s）→ 颜色渐变（亮黄→橙→暗红）→ 大小曲线（先大后收）→ 渲染模式（Additive 发光）+ 一个音效。这五条就是 5 分。

六、模型 · 骨骼 · 蒙皮 · Avatar课件 07 ★课件里直接点名美工

课件原话：美工：第三方软件建模 → 建骨骼 → 蒙皮 → 制作动画。
环节要点
建模第三方软件（3ds Max / Maya / Blender）做完导出，导入 Unity
建骨骼骨架层级；课件要求：骨盆位置的骨骼关节是所有骨骼的父层级，至少 15 个骨骼
蒙皮把网格顶点绑定到骨骼上，骨骼一动网格跟着变形（蒙皮网格 → Skinned Mesh Renderer）
制作动画在软件里做动作，导出动画剪辑；进 Unity 后配 Avatar + Controller

Avatar 与动画重定向

  • Avatar 的创建过程就是分析导入角色资源的骨骼结构，与 Mecanim 中已有的标准人类骨骼对比，最后自动转化或标识为 Mecanim 可识别的骨骼结构
  • 通过 Avatar 可以实现角色之间的 Retargeting（动画重定向）——把一个动画应用到多个不同模型的能力
  • 模型导入要求：T Pose（课件原话「模型要求 T Pose」）
  • 配置流程：选模型 → 属性面板 Rig 装配骨骼 → 出现打钩提示并生成 unitychanAvatar → 动画剪辑的 Rig 设 Humanoid → Copy From Other Avatar 选已建好的 Avatar
美工视角的加分句：Avatar 的意义是把「这份骨骼」翻译成「标准人形骨骼」，有了这层翻译，同一套走路/跑步动画就能给不同角色用，美术不用给每个角色重做动画。

七、界面用到的技术课件 08 ★老师 3:28 明确问的

老师问「界面用到什么技术」，这就是标准答案清单，按 Canvas → RectTransform → 控件 → 交互 四层答。

层要点
Canvas
画布		所有 UI 元素都要放在 Canvas 下面渲染。三种 Render Mode：
Screen Space - Overlay：UI 渲染在屏幕上，一直显示在最前面，分辨率变化自动适配
Screen Space - Camera：为 UI 指定一个相机，可为 UI 增加粒子特效，受相机设置影响；plane distance 设 UI 与相机距离；游戏相机 depth 设 −1、UI 相机 depth 设 0
World Space：UI 当成场景物体
RectTransform所有 UI 物体必须用 RectTransform，用来定义位置、大小、锚点、轴心。
Anchors（锚点）：Min/Max 是相对父物体的比例，Min=Max=(0,0) 表示锚点钉在父物体左下角，父物体缩放时锚点不动
Pivot（轴心）：(0.5,0.5) 是矩形中心，旋转/缩放/位置都以它为基准
Pos X/Y：轴心点相对锚点的坐标
控件Image：只能显示一个精灵；ImageType 有 Simple / Sliced（九宫格切片） / Tiled（平铺）/ Filled（填充）
Raw Image：可以显示任何纹理（视频、Render Texture）
Text / Button / Slider / Toggle
交互与资源Graphic Raycaster：UI 点击交互必备，自动挂在 Canvas 上，配合 EventSystem 检测点到了哪个 UI 元素；删掉它按钮就点不动
自动图集打包（Atlas）：把多张小图合成一张，减少 draw call
「界面用到什么技术」的标准 5 句（每题都能套）：
① Canvas + CanvasScaler 做画布和分辨率适配（固定 1920×1080 或 Match Width or Height）
② RectTransform 的锚点做自适应：四角元素锚定对应角，底栏锚定底部拉伸
③ Image（九宫格）+ RawImage 做底板和动态画面，图集合批降 draw call
④ Graphic Raycaster + EventSystem 让按钮能点
⑤ 用脚本订阅事件改 Text/Slider，不直接 Find 找 UI

九、示范：保卫萝卜（塔防）· 你是美工怎么答6 分写满版

按「职责 → 风格与规格 → 界面技术 → 表现反馈 → 和程序交接」五段写，每段 2~3 句。

段落写什么
① 职责范围我负责原画、建模、材质贴图、UI 界面、特效资源五项：先按策划文案做 2D 按线稿→上色→细节修饰→审查交付，再交建模做粗模/中模/高模→低模拓扑→UV→烘焙法线→材质→渲染。
② 风格与规格保卫萝卜是移动端休闲塔防，所以我选低多边形 + 高饱和卡通风格：角色 Q 版大头身，贴图控制在 512 以内并打成图集减少 draw call；场景用烘焙 Lightmap，因为塔和路面是静态的，烘焙后运行时不再算光照，省性能。
③ 界面技术
（老师明确问的）		界面用 UGUI：Canvas 用 Screen Space-Overlay，配 CanvasScaler 按 16:9 适配；金币/生命/波次数值区用锚点锚在顶部，塔选择栏锚在底部拉伸；按钮底板用 Image 的九宫格切片保证拉伸不变形；图标打图集；点击交互靠 Graphic Raycaster + EventSystem；弹窗用 Slider/Text 由脚本订阅事件刷新，不直接找 UI。
④ 表现与反馈塔攻击用粒子（发射形状 Cone 定向、Stretch Billboard 拉出弹道速度线、Additive 发光）；命中用飘字；塔升级用缩放 + 发光；怪物被击杀播爆炸粒子 + 音效；可走路径和不可走区域用地面贴图的颜色/纹理区分，让玩家一眼看懂路线。
