## 一、怎么运行

1. Unity Hub → Add → 选择本文件夹 `E:\Project\3DGame\AUST2024305305`，用 **2022.3.62f3c1** 打开。
2. 在 Project 窗口打开 `Assets/Scenes/Game.unity`。
3. 点 Play。

**不按 Play 也能看到画面。** 场景里除了挂 `GameBootstrap` 的 `GameRoot`，还有一个 `_Preview` 节点，
下面摆着背景平铺层、远景行星、星尘、玩家战机和标题 logo（共 60 个 SpriteRenderer）。
它负责的是「编辑状态下打开场景就能看到完整构图」，不至于是一片空黑色。

真正可玩的内容仍然全部由 `GameBootstrap` 在 Awake 里用代码搭出来，所以 `_Preview` 上挂了
`Core/ScenePreview.cs`：一进 Play 就把自己 `SetActive(false)` 再 `Destroy`，
否则会和运行时生成的背景、战机叠成两套。

> 为什么不把 `_Preview` 摆成真正的游戏对象：主菜单、HUD 这些要跟着状态机显隐、
> 要接事件、要按屏幕分辨率自适应，用代码构建比在场景里连引用更不容易出错。
> `_Preview` 只承担「让场景视图有东西看」这一件事，职责是清楚的。

**如果 Game.unity 打不开**（极少数情况下 Unity 对场景文件的兼容问题）：
新建一个空场景 → 新建空物体 → 挂上 `Assets/_Project/Scripts/Core/GameBootstrap.cs` → Play。
这样只会失去编辑模式预览，游戏本身完全一样。

**打包 exe**：File → Build Settings → Add Open Scenes（把 Game.unity 加进去）→ Build。
如果打包后粒子特效变粉块，把 `Legacy Shaders/Particles/Additive` 加入
Project Settings → Graphics → Always Included Shaders。

## 四、技术方案

### 4.1 分层架构

```
表现层  UI（HUD/菜单/结算）· 粒子 · 音频 · 镜头震动
   ↑ 只订阅事件
逻辑层  玩家 · 武器 · 子弹 · 敌人 FSM · Boss · 关卡波次
   ↑ 读取配置
数据层  EnemyConfig / WeaponConfig / LevelConfig / BossConfig（ScriptableObject）
   ↑ 调用服务
基础层  PoolManager · AudioManager · EventBus · GameManager
```

**单向依赖**是这套结构能被维护住的关键：UI 不知道血量怎么扣，敌人不知道分数怎么加，
全部通过 `EventBus` 广播。改玩法不会连带改界面。

### 4.2 对象池（性能核心）

子弹每秒可能生成十几发，如果每次 `Instantiate` + `Destroy`，会周期性触发 GC 造成卡顿。

```csharp
Dictionary<string, Queue<GameObject>>   // 池键 → 空闲队列
```

- **预热**：开局就创建好一批（子弹 40+30+70，敌人 10/8/8），避免第一次开火时卡一下
- **扩容**：池空了就现场补，永不返回 null，调用方不用判空
- **复位契约**：所有池对象实现 `IPoolable`，`OnSpawn()` 必须重置全部可变状态

> 这里踩过两个坑，都写进代码注释了：
> ① 子弹复用时没清速度/计时，会出现「新弹继承上一发位置」的鬼畜现象；
> ② 同一个对象被回收两次，会在队列里出现两份，之后被「生成两份」。`Despawn` 里用 `activeSelf` 挡住了。

`PoolManager.CreatedCount` 记录累计创建数，可以直接拿来做报告里的对比实验：
**开/关对象池两种模式下，同一段战斗的 Instantiate 次数与 GC Alloc 峰值。**

### 4.3 敌人状态机（FSM）

三种敌人共用一套状态骨架，差异只在两个虚方法上：

```
Spawning ──0.25s──▶ Active ──条件满足──▶ Attacking
                      ▲                     │
                      └──────攻击结束───────┘
                              HP ≤ 0
                                 ▼
                              Dying ──▶ 爆炸 → 加分 → 回收
```

| 敌人 | TickActive（移动） | TickAttack（攻击） |
|---|---|---|
| 直线冲锋 | 出生瞬间锁定方向，之后恒速直行 | 无远程攻击，靠碰撞伤害 |
| 停驻弹幕 | 下降到停驻高度后切状态 | 悬停 + 每 1.2 秒打三发扇形 |
| 追踪自爆 | 有限转向速度追向玩家 | 距离 1.1 内自爆，范围伤害 |

加第四种敌人只需要新增一个派生类，不用动基类——这是继承在这里的真正价值。

### 4.4 Boss 三阶段

| 阶段 | 血量 | 行为 |
|---|---|---|
| P1 | > 66% | 左右横移，每 1.5 秒 5 发扇形弹幕 |
| P2 | 33%~66% | 悬停中央，瞄准射击 + 每 5 次攻击召唤 2 只冲锋怪 |
| P3 | < 33% | 高速横移，每 1.0 秒 12 发旋转环形弹 |

阶段切换时停掉旧协程、起新的协程，每种形态是独立代码，互不干扰，也方便单独调。

### 4.5 美术与音频来源

**美术用 CC0 素材 + 程序化光效的混合方案。**

飞船、敌机、Boss、子弹、星空背景来自 Kenney 的 **Space Shooter Redux**（CC0 1.0，可商用、署名非强制）。
光斑、星云、粒子、引擎尾焰这些用代码生成——因为这类东西找不到尺寸合适的现成素材，
而且程序化生成能做到和任何飞船图都搭。

| 类型 | 来源 | 位置 |
|---|---|---|
| 飞船 / 敌机 / Boss / 子弹 / 星空背景 / 星点 | Kenney，CC0 | `Assets/_Project/Art/Resources/Sprites/` |
| 远景行星 `bg_planet`、标题字 `ui_logo` / `ui_logo_en` | 自制（Python 脚本离屏渲染） | 同上 |
| 辉光 / 星云 / 粒子 / 引擎尾焰 | 程序生成 | `Core/SpriteFactory.cs` |
| 7 种音效 | 程序合成 | `Core/SfxSynth.cs` |
| 背景音乐 `bgm_main.ogg` | OpenGameArt，CC0（作者 yd） | `Art/Audio/`，挂载在场景 `BGM` 节点 |

加载走 `Core/ArtLibrary.cs`，用 `Resources.Load` 按名取。**它是允许失败的**：
找不到资源就返回 `null`，调用方回退到 `SpriteFactory` 的程序化贴图，
并且 `ArtLibrary` 还会尝试自己从贴图切一张 Sprite 出来（防止导入设置不是 Sprite 2D and UI）。
这样即使某个 png 被误删或导入设置被改坏，游戏依然能跑，只是那一处变回程序化绘制。

版权与出处写在 `Assets/_Project/Art/CREDITS.txt`。

**为什么音效还是程序合成**：CC0 素材包里带的 sfx 只有 7 个，覆盖不了激光/散射/爆炸/受击/受伤/UI/警报六类；
自己合成反而更统一，也不占体积。

**为什么 BGM 用文件而不是合成**：4 分钟的音乐按流式加载常驻内存只有几十 KB，
而合成 4 分钟等于在内存里展开 40 MB 的 PCM；更重要的是**换曲子不该改代码**——
把另一个 ogg 拖到场景 `BGM` 节点的 AudioClip 槽里就行。音效反过来：几十毫秒的短音，
做成文件反而多出一堆资源要管。

### 4.6 碰撞方案

- 玩家：Dynamic 刚体（velocity 驱动），触发器
- 敌人：Kinematic 刚体，触发器
- 子弹：Dynamic 刚体 + Continuous 连续检测，velocity 驱动

**为什么不用 transform.Translate 移动子弹**：物理引擎按固定步长推进刚体，
触发器检测才不会因为帧率波动漏判（高速穿透）。**为什么每对碰撞里至少有一方是 Dynamic**：
Box2D 的 Kinematic-Kinematic 组合不上报接触，两方都设 Kinematic 会导致子弹打不中。

### 4.7 视觉方案

**背景按景深分层。** 单色纯黑 + 一堆小星点是最显「空」的组合——没有参照物，玩家看不出自己在动。现在从远到近压了七层：

| 层 | 内容 | sortingOrder | 作用 |
|---|---|---|---|
| 1 | 星空底图平铺（256² 贴图 × 4×3 格） | -120 | 给画面底色，去掉「死黑」 |
| 2 | 星云 ×7（紫/品红/青三色轮换） | -110 | 大尺度色块，撑住画面 |
| 3 | 远景行星（球面光照 + 气态条带 + 边缘光） | -105 | 唯一的「大物体」，提供体积感与距离感 |
| 4 | 星点 ×3 层视差 | -100 ~ -96 | 远层小而暗、近层大而亮且带十字星芒 |
| 5 | 透视网格 + 地平线辉光 | -93 ~ -91 | 赛博朋克的地面线，也是「在前进」的最强参照 |
| 6 | 流星 ×4 | -80 | 偶发的横向动势 |

关键细节：**横向网格线按 p 的平方分布**（`t = p * p`）。屏幕上的 y 与地面距离不是线性关系，直接用线性间距会看起来像「贴纸」而不是地面。

**平铺背景的两个坑**（都是踩过之后改的）：

1. 贴图四周有一圈很淡的暗边。严丝合缝地拼起来，边界会连成整齐的方格接缝，一眼就能看出「这是同一张图重复的」。
   解法是每块放大 8% 让边缘互相压住；**不能**用「每块随机调明暗」去打破重复——纯色底上相邻块亮度不同，接缝反而更明显。
2. 缩放值要按素材实际尺寸换算。素材星点只有 25×24 像素、100 PPU（即 0.25 单位），
   而旧代码里的 `localScale` 是按「1 单位精灵」写的，直接套上去星点会小到几乎看不见。
   现在 `localScale = 1` 只画出 0.25 单位，所以最近的星层要写到 1.15~1.80 才有 0.4 单位左右。

**战机重画。** 旧版只有一个连续公式 + 大范围 alpha 渐变，出来是一块糊的蓝斑。新版把轮廓拆成四段（机身 / 三角后掠翼 / 鸭翼 / 尾翼），每个像素先判部件再上色，最后压一圈深色描边把剪影从背景里拉出来；再挂 3 个推进器（双引擎 + 一条长尾迹，`ThrusterPulse` 做双频抖动）和 2 个翼尖航行灯。静态发光点看着像贴纸，抖动起来才有「引擎在烧」的感觉。

**界面统一走主题 + 面板基类。** `UITheme` 收所有颜色与字号，`UIPanelBase` 统一用 `CanvasGroup.alpha` 做淡入淡出——不用 `SetActive(false)`，因为那会触发 `OnDisable` 让面板退订事件，再次显示时血条会停在旧数值上。淡入用 `unscaledDeltaTime` 推进，否则暂停面板（`timeScale = 0`）永远淡不进来。

### 4.8 主菜单与设置面板（第 8 章 UGUI）

主菜单不再是「按回车开始」，而是三个真按钮：

```
开始游戏     → GameManager.StartGame()
设置         → 打开 SettingsPanel（主菜单淡出）
退出游戏     → Application.Quit()；编辑器下改为停止播放
```

键盘快捷键（`Enter`）保留了，但它和点按钮走的是同一个入口，不存在两套逻辑。

**几处刻意的处理：**

- 按钮底色 `Image` 的 `raycastTarget` 必须是 `true`。`UIFactory.CreateImage` 统一把它关掉了（装饰件不该挡射线），
  所以按钮要自己加回来，否则点了没反应。
- 悬停效果没用 `Button` 自带的 `ColorTint`。`ColorTint` 是把颜色**乘**在底图上，
  想变亮就得给大于 1 的值，但结果会被钳到白色、把底色冲掉。
  改成在按钮上叠一层透明青色（`UIButtonFx` 用 `IPointerEnterHandler` 插值 alpha），
  再把左侧竖条变粗变亮、文字从灰变青——就是赛博界面那种「局部点亮」。
- `Slider` 的 `fillRect` / `handleRect` 必须各自套一层中间节点（`FillArea` / `HandleArea`），
  这是 UGUI Slider 的固定结构：它会自己改写这两个节点的锚点，直接挂在根上会算错位置。
- **设置页的两根推子是自己画的**（`UISprites.Sheet(3f)` 做圆角轨道 + 刻度 + 方块手柄），
  没有直接用 `Slider` 默认外观：默认外观是 Unity 的一整套灰蓝贴图，混在切角面板里非常出戏。
  逻辑仍然用真正的 `Slider` 组件，只是把 `targetGraphic` 关掉、自己画表现层。
- 子面板（机库 / 图鉴 / 说明 / 设置 / 选关）没有进 `GameState` 状态机。状态机管的是「在不在打游戏」，
  这些只是盖在主菜单上的一层，谁打开谁负责关。
  代价是 `GameManager` 要判断 `Menu.SubPanelOpen`，否则玩家在设置里按回车会直接开局、面板却还挂在屏幕上。
- 主菜单从「三个按钮」扩到六项之后，键盘和鼠标都保留了：`↑↓` 逐项高亮（首行默认高亮），
  `Enter` 进当前项，鼠标悬停会同步高亮——两条路径最后调的都是同一个 `Button.onClick`。

### 4.9 界面重做：一套「战术终端」视觉体系

第一版界面是"每页各画各的"：颜色直接写 `new Color(...)`、字号随手给 24/26/28、
每个面板自己搭一个直角底框，结果十来个页面看起来像十来个不同的游戏。
第二版不再按页修，而是先做一层**视觉基础层**，所有页面只允许用这层拼装：

| 文件 | 职责 |
|---|---|
| `UI/UITheme.cs` | 唯一的颜色 / 字号 / 间距 / 切角来源（四档表面、四档描边、11 档字号） |
| `UI/UISprites.cs` | **程序化精灵**：45° 切角九宫格底板与描边环、竖/横渐变、网格、点阵、危险斜纹 |
| `UI/UIChrome.cs` | 界面骨架：`Sheet`（切角面板 + 辉光 + 四角取景框 + 顶部强调条）、`Header`（编号徽章 / 标题 / 英文副标）、`Footer`、`Action`（列表行 / 主按钮 / 幽灵按钮）、`Tag`、`KeyHint`、`Hairline`、`VLine`、`Bracket`、`Scrim`、`GridBackdrop` |
| `UI/UIWidgets.cs` | 分段血条 `UISegBar`、刻度条 `UIMeter`、扫光 `UISweep`、呼吸 `UIBreathe`、网格漂移 `UIGridDrift` |
| `UI/UIFactory.cs` | 字体解析（正文 + 等宽）、文字 / 图片 / 按钮 / 滑条工厂、`SpaceOut` 字距 |
| `Docs/UI_STYLE.md` | 上面这套的书面规范（八条硬纪律 + 骨架模板 + 验收标准） |

**没有一张切角底图，全部是运行时画出来的。** `UISprites.Sheet(cut)` 用有符号距离场生成
45° 切角矩形，按 `border = cut` 做成九宫格——所以同一张 44×44 的贴图能拉成 1240×980 的面板，
切角不会被拉变形，放大到 4K 也不糊。`SheetEdge(cut, thickness)` 同理生成描边环，
于是"底板 + 一圈细描边 + 内侧一道白色微光"这套质感零素材成本。

**几个刻意的决定：**

- **选中态不用"刷底色"**。第一版给选中卡片的底板刷一层半透明强调色，结果底板一透明，
  背后的同色辉光整个透出来，卡片变成一块实心色块，比旁边亮一大截。
  现在底板永远是同一个深色，选中信号只交给**描边、外辉光、名字颜色、顶部强调条**四样。
- **数字和英文标签走等宽字体**，中文走正文字体（等宽字体基本没有汉字）。
  分数、血量、`HP 022`、`067%` 这类读数用等宽，数值滚动时不会左右抖动；
  拉丁小标题再用 `SpaceOut` 逐字加字距，赛博界面那种"拉开的微型大写"就出来了。
- **手写锚点前先想清楚"这个坐标相对谁"**。第一版图鉴和帮助页把
  `anchor=(0,0.5)`（左边缘）和"相对中心"的负偏移混用，整块内容画到了面板外面——
  面板类改用 `anchor=(0.5,0.5)` + `pivot=(0,0.5)`，让 `-40` 真的表示"中心往左 40"。
- **渐变必须按方向生成**。把竖向渐变 `localScale.x` 压扁 / 旋转 90° 当横向渐变用时，
  有效宽度会变成屏幕高度，暗坡在中途断掉，左边留一条硬竖边；
  后来补了 `UISprites.GradientH()`，菜单左右两侧的暗坡才真正化开。
- **所有界面动效走 `unscaledDeltaTime`**，否则暂停面板（`timeScale = 0`）永远淡不进来。

验收方式也很土但有效：写了一个 Editor 脚本（`Assets/Editor/UIShotCapture.cs` + `UIShotFlow.cs`），
自动进 Play 模式、逐屏切状态、把 UGUI 渲进 1920×1080 的 RenderTexture 再 `ReadPixels` 存 PNG，
一共 10 张（标题 / 菜单 / 选关 / 图鉴 / 设置 / 说明 / HUD / 暂停 / 结算）。
比肉眼盯 Game 视图可靠：每张图都算平均亮度与 UI 覆盖率，黑屏、漏建面板当场就能发现。

## 六、想改数值改哪里

## 七、已知限制

1. 中文字体来自系统（微软雅黑 / 黑体 / 等线 / 宋体），不随工程打包。换到没有中文字体的机器上会回退成方块；
   要彻底摆脱这个依赖，把字体文件拖进 `Assets/_Project/Art/` 再把 `ResolveFont()` 改成 `Resources.Load<Font>` 即可。
2. Boss 召唤小怪时如果同时被击杀，极端情况下关卡计数可能短暂不准（已加保护，不影响流程）。
3. 所有界面仍然由代码构建，Hierarchy 里只有一个 `_Preview` 预览层看得见。
   这样做是为了「界面要跟着状态机显隐、要接事件、要自适应分辨率」时不用在场景里连一堆引用；
   代价是不方便在 Inspector 里调像素级的间距。真要做可视化编辑，就得改成 Prefab 工作流。
4. 面板是半透明的（底板 alpha 0.94），背后的星云会隐约透上来——这是刻意的「全息投影」质感，
   但如果把面板拖到最亮的星云上，文字对比度会下降。
5. 截图流水线（`Assets/Editor/`）只在编辑器里可用，且手动改了 `Build` 常量才会重跑；
   正式版本应该把它从打包流程里排除（放在 `Editor` 目录已经保证不打进包）。
6. 未做移动端适配（输入是键盘 + 鼠标），分辨率按 1920×1080 设计，
   用 `CanvasScaler` 的 `MatchWidthOrHeight = 0.5` 做等比缩放，超宽屏下左右会留出更多余量。
