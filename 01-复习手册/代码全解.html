A1 · 自转 sr.cs 与公转 ra.cs课件 01 · slide 50
public class sr : MonoBehaviour {
    public float frs = 1f;
    void Start () {
    }    
    void Update () {
        this.transform.Rotate(Vector3.up* frs, Space.World);
    }
}

public class ra : MonoBehaviour {
    public float frs = 1f;
    public Transform trans;
    void Start () {
    }    
    void Update () {
        this.transform.RotateAround(trans.position, Vector3.up,frs);
    }
}
代码作用
Rotate(Vector3.​up* frs,​ Space.​World)绕 Y 轴每帧转 frs 度。这里 Vector3.up* frs 被当作欧拉角解释（第二个参数是 Space 时，第一个参数是欧拉角）。
Space.​World按世界坐标系的 Y 轴转；写 Space.Self 就是按自身 Y 轴转。物体没倾斜时两者结果一样，一旦父物体歪了两者就不同。
RotateAround(trans.​position,​ Vector3.​up,​ frs)公转：绕 trans 这个点、以 Vector3.up 为轴、转 frs 度。三个参数依次是「点、轴、角度」，顺序不能乱。
public Transform trans在 Inspector 里把「太阳」拖进来。没有赋值就会空引用报错，所以必须先在面板上拖。
public float frs = 1fpublic 变量会显示在 Inspector，运行时改的值不会保存（停 Play 就打回原值）。
这道题的考点：Rotate 和 RotateAround 的区别。Rotate 只改 rotation，物体位置不动，所以是自转；RotateAround 要绕别的点转，所以同时改 position 和 rotation，是公转。试卷上问「哪个会改变 position」——答案是 RotateAround。
课件这里的签名不严谨：PPT 第 3 章写的是 Rotate(Vector3 eulerAngles, float relativeTo)，第二个参数写成了 float，实际应该是 Space。Unity 真正的两个重载是：
Rotate(Vector3 eulerAngles, Space relativeTo)
Rotate(Vector3 axis, float angle, Space relativeTo)。考试如果按 PPT 出，你写 PPT 那版；如果考严格的 API，你写后面这版。

代码作用
go = (GameObject)o;错。o 声明成 Object，编译器不允许把父类直接强转成子类，除非你先确定它真是那个子类（用 as 或先 is 判断）。
o = (Object)go;对。子类转父类叫向上转型，永远安全，甚至不写 (Object) 也行（隐式转换）。
o = go as Object;对。as 是「转换运算符」，转不成功会返回 null 而不是抛异常。
print(o)print() 是 MonoBehaviour 提供的方法，等价于 Debug.Log()，输出到 Console。
考点：as 和 () 的三条差别
① 强转 () 失败会抛异常；as 失败返回 null。
② as 只能用于引用类型（和可空类型），不能用于 int 这种值类型。
③ 强转能双向转（配合 is 判断）；as 一般只用于向下转。
实验一的 GameObject.Find("Game").GetComponent<Game>() as Game 就是 as 的典型用法。

① ArrayList 非泛型，存 object，有装箱拆箱开销；List<T> 泛型，无装箱。
② ArrayList 类型不安全（能混装）；List 编译期就有类型检查。
③ 两者都用 Count 取长度。

// ① 定义枚举（写在类外或类内）
public enum PlayerType { Soldier, Doctor, Monster };

// ② 在类里声明一个枚举类型字段
public PlayerType player;

// ③ switch 使用
switch (player) {
    case PlayerType.Soldier:
        ……
        break;
    ……
}

// ④ 完整脚本：撞到 Monster 类型的东西就自我销毁
public class Test : MonoBehaviour {
    public PlayerType player;
    void Start () {    }
    void Update () { }
    void OnCollisionEnter(Collision collisionInfo) {
        Test other = collisionInfo.gameObject.GetComponent<Test>();
        if (other && other.player == PlayerType.Monster) {
            Destroy(this.gameObject);
        }
    }
}
代码作用
public enum PlayerType { Soldier,​ Doctor,​ Monster };枚举 = 一组有名字的常量。默认 Soldier=0、Doctor=1、Monster=2，依次加一。写在类外面是全局枚举，写在类里面是嵌套枚举。
public PlayerType player;声明一个枚举字段。因为 public，Inspector 里会变成一个下拉框——这就是课件标题说的「Unity 中可选择枚举值」。
collisionInfo.​gameObject.​GetComponent​<Test>()从撞到的那个物体上取 Test 组件。注意是 collisionInfo.gameObject，不是 this.gameObject。
if (other && other.​player == PlayerType.​Monster)两个判断合成一句：other 非空（取不到组件时返回 null，不判空就直接 other.player 会崩），且它是 Monster 类型。
Unity 的 Object 支持隐式转 bool，所以能直接写 if (other)，等价于 if (other != null)。
Destroy(this.​gameObject)销毁当前物体。this.gameObject 和 gameObject 等价。
考点：为什么能写 if (other)。这来自 UnityEngine.Object 重载了 operator bool 和 operator ==。Unity 的对象“已销毁”和“null”是两回事：销毁后的对象引用不为 null，但 == null 会返回 true。这就是为什么推荐 if (obj) 而不是 if (obj != null)。
A6 · 协程的启动与停止课件 02 · slide 35-36
public class MyTest : MonoBehaviour {

    private Coroutine m_Coroutine = null;

    IEnumerator CreateCube() {
        for (int i = 0; i < 10; i++) {
            GameObject.CreatePrimitive(PrimitiveType.Cube).transform.position =
                Vector3.one * i;
            yield return new WaitForSeconds(1f);
        }
    }

    void OnGUI() {
        if (GUILayout.Button("StartCoroutine")) {
            if (m_Coroutine != null) {
                StopCoroutine(m_Coroutine);
            }
            m_Coroutine = StartCoroutine(CreateCube());
        }
        if (GUILayout.Button("StopCoroutine")) {
            if (m_Coroutine != null) {
                StopCoroutine(m_Coroutine);
            }
        }
    }
}
代码作用
IEnumerator CreateCube()协程的返回类型必须是 IEnumerator（迭代器），不是 void。这是最容易写错的地方。
yield return new WaitForSeconds(1f)暂停 1 秒再往下执行。每一轮循环都等 1 秒，所以 10 个方块是每秒冒一个。
GameObject.​CreatePrimitive(PrimitiveType.​Cube)静态方法，直接造一个基础几何体（Cube/Sphere/Cylinder/Plane/Capsule/Quad）。返回新建的 GameObject。
Vector3.​one * iVector3.one = (1,1,1)，乘 i 就是 (i,i,i)，所以方块沿对角线排开。
m_Coroutine = StartCoroutine(CreateCube())StartCoroutine 返回一个 Coroutine 句柄，存下来才能定向停止。
StopCoroutine(m_Coroutine)按句柄停止。也有 StopCoroutine("方法名") 的字符串版本，但那需要方法有参数或至少用字符串重载才稳。
GUILayout.​Button(".​.​.​")OnGUI 里的即时模式 GUI 按钮，返回 bool 表示这一帧是否被点。注意它和 UGUI 的 Button 完全是两套东西。
考点：协程的 5 种 yield 写法（课件 slide 34 明写）
yield return null; → 等一帧
yield return new WaitForFixedUpdate(); → 等到下一次 FixedUpdate
yield return new WaitForSeconds(k); → 等 k 秒（受 timeScale 影响）
yield return StartCoroutine("Other"); → 等另一个协程结束
yield break; → 直接结束协程（PPT 没写，但常考）
协程什么时候会停：物体 SetActive(false) 会停、脚本 enabled = false 会停、Destroy 会停。这一点和 Update 一致。

private Color[] colors = new Color[] {
    Color.red, Color.yellow, Color.blue, Color.green, Color.white
};

public GameObject text;
public float destoryTime;        // 注意：老师把 destroy 拼成了 destory，照抄即可

void Start() {
    text = GameObject.Find("Text1");
    destoryTime = Time.time;
}

void Update() {
    if (Input.GetMouseButtonDown(0)) {
        text.SetActive(true);

        TextMesh t = text.GetComponent<TextMesh>();
        t.text = "-" + Random.Range(1, 100).ToString();
        t.color = this.colors[Random.Range(0, this.colors.Length)];

        text.transform.position = this.transform.position
            + new Vector3(Random.Range(-0.1f, 0.1f), Random.Range(0.1f, 0.2f), 0f) * 10f;

        destoryTime = Time.time;
    }

    if (Time.time - this.destoryTime <= 1f)      // 1 秒钟后消失
        text.transform.Translate(new Vector3(0f, 0.05f, 0f));
    else
        text.SetActive(false);
}
代码作用
private Color[] colors = new Color[] { .​.​.​ }一个颜色数组当场初始化，用来给飘字随机取色。private 所以不在 Inspector 显示。
GameObject.​Find("Text1")按名字找物体，返回 GameObject。找不到返回 null。性能差，只在 Start 里调一次是对的写法；放 Update 里会有人说你。
Input.​GetMouseButtonDown(0)鼠标左键按下那一帧返回 true。0=左键、1=右键、2=中键。对比：GetMouseButton 按住一直 true，GetMouseButtonUp 松开那一帧 true。
text.​SetActive(true)把物体激活。注意 SetActive 是物体级开关，enabled 是组件级开关，两者别混。
t.​text = "-" + Random.​Range(1,​ 100).​ToString()Random.Range(int, int)：返回 int，右端不包含，所以是 1~99。
Random.Range(float, float)：返回 float，右端包含。这个不对称是必考点。
t.​color = this.​colors[Random.​Range(0,​ this.​colors.​Length)]this.colors.Length = 5，Range(0,5) 取 0~4，正好是合法下标。这里写 Length 而不是 Length-1，正是利用了上面那条“右端不包含”。
Time.​time - this.​destoryTime ​<= 1fTime.time 是游戏开始到现在的秒数（受 timeScale 影响，暂停时不走）。两个 time 相减 = 经过了多久。
text.​transform.​Translate(new Vector3(0f,​ 0.​05f,​ 0f))每帧往上飘 0.05 单位。注意这里没乘 Time.deltaTime，所以飘的速度跟着帧率变——这是课件的瑕疵，标准写法应该乘 deltaTime。
必背：Random.Range 的两种重载
Random.Range(int min, int max) → 返回 int，范围 [min, max)，右端不含
Random.Range(float min, float max) → 返回 float，范围 [min, max]，右端含
实验一 FoodSpawner 里的 (int)Random.Range(borderLeft.position.x+0.5f, ...) 用的是 float 版再强转，注意这个区别。
考点：TextMesh 的三个属性：.text（内容）、.color（颜色）、.fontSize（字号）。
课件给的清晰化技巧：先把 Font Size 调到 80，再缩小 Scale——因为 TextMesh 是按字号渲染位图，字号小的时候拉大会糊。

代码作用
Vector3 v = obj2.​position - obj1.​position终点减起点，得到「从 obj1 指向 obj2」的向量。顺序反了结论就全反了。
TransformDirection(Vector3.​forward)把「本地前方」翻成世界方向。因为 transform.forward 本身就是世界空间的前方，这里其实等价于 obj1.transform.forward。

v1·v2 = x1x2 + y1y2 + z1z2 = |v1||v2|cosθ
v1·v2 > 0 → 0° ≤ θ < 90°，两向量大致同向
v1·v2 = 0 → θ = 90°，垂直
v1·v2 < 0 → 90° < θ ≤ 180°，反向
两个都是单位向量时，Dot 就等于 cosθ，范围 [−1, 1]。
A15 · 叉乘求平面法线（正面朝向）课件 04 · slide 7
Vector3 side1 = objc.transform.position - obja.transform.position;

代码作用
objc.​position - obja.​position从 a 指向 c 的一条边。
objb.​position - obja.​position从 a 指向 b 的另一条边。两条边共用同一个起点 a，这是关键。
Vector3.​Cross(side1,​ side2)叉乘 → 得到同时垂直于两条边的向量，也就是这个三角形平面的法线。
normal.​Normalize()单位化，让长度变成 1。叉乘结果的长度 = |a||b|sinθ，不是单位长度，求法线必须单位化。
必背：叉乘公式与性质
v1 × v2 = (y1z2 − z1y2,　z1x2 − x1z2,　x1y2 − y1x2)
反交换律：v1 × v2 = −(v2 × v1)　→　换顺序法线就翻转
长度：|v1×v2| = |v1||v2|sinθ　→　不等于 1，必须 Normalize
方向：右手定则，同时垂直于 v1 和 v2
用途：求平面法线 / 求旋转轴（见 A16）
叉乘算不准就背这个口诀：求哪个分量，就把它划掉，剩下两个轴按 x→y→z→x 循环排，前一个放第一项。
求 x 分量：划掉 x，剩 y、z → 排成 y1z2，再反过来 z1y2，相减 → y1z2 − z1y2
求 y 分量：划掉 y，剩 z、x → z1x2 − x1z2（注意这里顺序是 z 在前）
求 z 分量：划掉 z，剩 x、y → x1y2 − y1x2
你上次错在 y 分量把减数和被减数颠倒了，就是没记住「z 在前」。
A16 · 跟随 + 平滑转向（Slerp）与手写转向（Cross）★课件 04 · slide 8
public Transform target;
public float moveSpeed = 3f;
public float rotationSpeed = 50f;
public Vector3 positionOffset = new Vector3(0, 1, -3);
public bool lookAtTarget = true;

void Update() {
    if (target != null)
        FollowTarget();
}

void FollowTarget() {
    // 计算目标位置
    Vector3 targetPosition = target.position + positionOffset;

    // 移动：线性插值
    transform.position = Vector3.Lerp(transform.position, targetPosition,
                                      moveSpeed * Time.deltaTime);

    // 旋转：先求目标朝向，再球面插值
    Vector3 direction = (target.position - transform.position).normalized;
    Quaternion targetRotation = Quaternion.LookRotation(direction);
    transform.rotation = Quaternion.Slerp(transform.rotation, targetRotation,
                                          rotationSpeed * Time.deltaTime);
}

private void RotateTowardsTargetPure() {
    // 自身指向目标的方向
    Vector3 directionToA = (target.position - transform.position).normalized;
    // 叉乘得到旋转轴
    Vector3 cross = Vector3.Cross(transform.forward, directionToA);
    // 当前前方与目标方向的夹角
    float angle = Vector3.Angle(transform.forward, directionToA);

    if (angle > 5) {                       // 5 度死区
        float rotationAngle = Mathf.Min(rotationSpeed * Time.deltaTime, angle);
        transform.Rotate(cross, rotationAngle, Space.World);
    }
}
代码作用
Vector3.​Lerp(a,​ b,​ t)线性插值：a + (b−a)*t。t=0 返回 a，t=1 返回 b。t 应该夹在 0~1，课件没夹，是瑕疵。
Quaternion.​LookRotation(direction)方向 → 旋转。让物体的前方（+Z）对准 direction。参数是方向，不是位置——写 LookRotation(target.position) 是错的。
Quaternion.​Slerp(a,​ b,​ t)球面线性插值，第三个参数是 0~1 的比例。角速度均匀，所以转向看起来平滑不突兀。
(target.​position - transform.​position).​normalized先求方向再单位化。不单位化的话 Lerp/Slerp 的比例会被距离放大。
Vector3.​Cross(transform.​forward,​ directionToA)叉乘得旋转轴。顺序决定转向：forward × 目标方向 才是「朝目标转」，反了就背对着转。
float angle = Vector3.​Angle(a,​ b)返回两向量夹角，单位是度，范围 0~180。内部就是 Acos(Dot)。
if (angle > 5)死区：差 5 度以内就不转了。防止在目标附近来回抖动。
Mathf.​Min(rotationSpeed * Time.​deltaTime,​ angle)限速 + 防过冲：这一帧最多转这么多，但也不能超过剩下要转的角度。没有 Mathf.Min 就会转过头再回摆。
transform.​Rotate(cross,​ rotationAngle,​ Space.​World)三参数重载：绕 cross 轴转 rotationAngle 度，轴按世界坐标解释。
★ 这就是今天那道选择题的原文。考点有三个：
① 代码只改 rotation 不改 position → 功能是「一直面向目标」
② Cross(forward, 目标方向) = 旋转轴，顺序反了会背对目标转
③ Mathf.Min(限速×dt, 剩余角度) = 限速且不过冲，这个骨架要背下来
Quaternion 五成员（必背）
identity　无旋转（w=1），常用于 Instantiate 第三个参数
Euler　　 欧拉角 → 四元数，Quaternion.Euler(0,90,0)
LookRotation　方向 → 旋转，参数是方向
Slerp　　 球面插值，第三参数是比例 0~1
AngleAxis　绕轴转多少度，Quaternion.AngleAxis(30, Vector3.up)
陷阱：Slerp 第三参数是比例，RotateTowards 第三参数是角度，两者容易混。
两个可以拿来说明的瑕疵：① Vector3.Lerp 的 t 没做 Mathf.Clamp01，速度大时 t>1 会冲过头；② Slerp 同理。答辩或答题时指出这一点，会显得你真的读懂了。
A17 · 网格合并与材质合并课件 04 · slide 14
void Start() {
    //---------------- 先获取材质 -------------------------
    // 获取自身和所有子物体中所有 MeshRenderer 组件
    MeshRenderer[] meshRenderers = GetComponentsInChildren<MeshRenderer>();
    Material[] mats = new Material[meshRenderers.Length];
    for (int i = 0; i < meshRenderers.Length; i++) {
        mats[i] = meshRenderers[i].sharedMaterial;
    }

    //---------------- 合并 Mesh --------------------------
    // 获取自身和所有子物体中所有 MeshFilter 组件
    MeshFilter[] meshFilters = GetComponentsInChildren<MeshFilter>();
    CombineInstance[] combine = new CombineInstance[meshFilters.Length];

    for (int i = 0; i < meshFilters.Length; i++) {
        combine[i].mesh = meshFilters[i].sharedMesh;
        // 矩阵：自身空间坐标的点 → 世界空间坐标的点
        combine[i].transform = meshFilters[i].transform.localToWorldMatrix;
        meshFilters[i].gameObject.SetActive(false);
    }

    // 为新的整体新建一个 mesh
    transform.GetComponent<MeshFilter>().mesh = new Mesh();
    // 合并 Mesh。第二个 false 参数表示不合并为一个网格，而是子网格列表
    transform.GetComponent<MeshFilter>().mesh.CombineMeshes(combine, false);

    transform.gameObject.SetActive(true);

    // 为合并后的新 Mesh 指定材质
    transform.GetComponent<MeshRenderer>().sharedMaterials = mats;
}
代码作用
GetComponentsInChildren​<T>()取自身 + 所有子物体上的组件，返回数组。对比 GetComponent（只取自己、单个）、GetComponents（只取自己、多个）。
sharedMaterial 而不是 material关键区别：material 会复制一份新材质（改了不影响别人，但会漏内存）；sharedMaterial 直接拿共享的那个（改了大家一起变）。这里只是读取，所以用 shared。
CombineInstance[] combine合并用的结构体数组。每个元素装两个东西：.mesh（哪个网格）和 .transform（它原来在世界里的位置矩阵）。
meshFilters[i].​transform.​localToWorldMatrix本地变世界的 4×4 矩阵。没有这一步，所有零件会被叠在原点。
meshFilters[i].​gameObject.​SetActive(false)合并完把原零件隐藏，不然会和合并后的新模型重叠显示。
new Mesh()必须 new，不能直接用子物体的 mesh 覆盖。

B1 · Snake —— 蛇头移动、吃食物、长身体实验一 · 内容.doc
using System.Linq;

public class Snake : MonoBehaviour {
    Vector3 dir = Vector3.right;
    List<Transform> tail = new List<Transform>();
    bool ate = false;
    public GameObject tailPrefab;   // Tail Prefab
    public bool work = false;

    void Start() {
        InvokeRepeating("Move", 1f, 0.3f);
    }

    void OnTriggerEnter(Collider other) {
        if (other.gameObject.tag.Equals("food")) {
            ate = true;
            Destroy(other.gameObject);
        }
        else {
            work = false;
            //Game game = GameObject.Find("Game").GetComponent<Game>() as Game;
            //game.StopGame();
        }
    }

    void Update() {
        if (Input.GetKey(KeyCode.RightArrow))      dir = Vector3.right;
        else if (Input.GetKey(KeyCode.DownArrow))  dir = Vector3.down;
        else if (Input.GetKey(KeyCode.LeftArrow))  dir = Vector3.left;
        else if (Input.GetKey(KeyCode.UpArrow))    dir = Vector3.up;
    }

    void Move() {
        if (work) {
            Vector3 v = transform.position;
            transform.Translate(dir);

            if (ate) {
                GameObject g = (GameObject)Instantiate(tailPrefab, v, Quaternion.identity);
                tail.Insert(0, g.transform);
                ate = false;
            }
            else if (tail.Count > 0) {
                tail.Last().position = v;
                tail.Insert(0, tail.Last());
                tail.RemoveAt(tail.Count - 1);
            }
        }
    }
}
代码作用
using System.​Linq;为 tail.Last() 服务。Linq 的扩展方法在 System.Linq 里，不写这句编译不过。这句是常考细节：问“为什么要 using System.Linq”。
Vector3 dir = Vector3.​right初始方向朝右。注意没写访问修饰符 = private（C# 字段默认 private）。
List​<Transform> tail用一个 List 存所有尾巴节。存 Transform 而不是 GameObject，因为只需要 position。
InvokeRepeating("Move",​ 1f,​ 0.​3f)重复调用：1 秒后第一次执行，之后每 0.3 秒执行一次。
三个参数：方法名（字符串，带引号）、首次延迟、重复间隔。
⚠️ 课件第 2 章写的是 InvokeRepeat()，Unity 里没有这个方法。
other.​gameObject.​tag.​Equals("food")触发器回调参数是 Collider，取 tag 要先 .gameObject 或直接 other.tag。
Destroy(other.​gameObject)销毁食物，不是蛇自己。
else { work = false; }撞到不是 food 的东西 → 游戏结束（后面注释掉的两行是通知 Game 脚本）。
Vector3.​right / down / left / up注意方向：这是 2D 竖版贪吃蛇，Y 轴当上下，所以用 up/down 而不是 forward/back。
Vector3 v = transform.​position;先存下旧位置，因为下一行就要动了，尾巴要挪到「头刚才在的地方」。
transform.​Translate(dir)默认按 Space.Self 平移。每 0.3 秒移动 1 个单位。
Instantiate(tailPrefab,​ v,​ Quaternion.​identity)三参数实例化：预制体、位置、旋转。Quaternion.identity = 不旋转。
tail.​Insert(0,​ g.​transform)插到下标 0（头部），因为尾巴是从头往尾数的。
tail.​Last().​position = v把尾巴末端挪到蛇头刚才的位置——这是贪吃蛇的核心技巧：不移动所有节，只移动最后一节。
tail.​Insert(0,​ tail.​Last()); tail.​RemoveAt(tail.​Count - 1);再把刚挪过来的那一节移到队首，同时把队尾删掉（它已经插到前面了）。这就是「整条尾巴往前蠕动一格」的实现。
这道题的三个高频考点
① InvokeRepeating(方法名, 首次延迟, 间隔) —— 参数顺序和含义
② Instantiate(预制体, 位置, 旋转) —— 三个参数
③ Quaternion.identity = 无旋转，你已经错两次了
附加考点：Instantiate(prefab, pos) 两参数版和 Instantiate(prefab, pos, Quaternion.identity) 完全等价。
“为什么只移动最后一节？”——这是设计题会问的点。如果每节都计算自己该去哪，代码复杂且容易错；只把最后一节挪到新位置再插到队首，其余节位置不变，视觉上就是整条蛇前进了。这是用数据结构操作替代逐元素计算的典型思路。
B2 · FoodSpawner —— 定时在边界内随机刷食物实验一 · 内容.doc
public class FoodSpawner : MonoBehaviour {

    public GameObject foodPrefab;

    // Borders
    public Transform borderTop;
    public Transform borderBottom;
    public Transform borderLeft;
    public Transform borderRight;

    public bool Continuous = false;

    void Start() {
        InvokeRepeating("Spawn", 1, 4);   // 每 4 秒钟生成一个食物
    }

    void Spawn() {
        if (Continuous) {
            int x = (int)Random.Range(borderLeft.position.x + 0.5f,
                                      borderRight.position.x - 0.5f);
            int y = (int)Random.Range(borderBottom.position.y + 0.5f,
                                      borderTop.position.y - 0.5f);

            // Instantiate the food at (x, y)
            Instantiate(foodPrefab, new Vector3(x, y, -0.5f), Quaternion.identity);
        }
    }
}
代码作用
InvokeRepeating("Spawn",​ 1,​ 4)1 秒后开始，之后每 4 秒一次。注意这里写的是整数 1, 4，隐式转成 float，也能编译。
public Transform borderTop / Bottom / Left / Right四个边界物体，在 Inspector 里拖四个 Board 进去。用 Transform 是为了取 .position。
public bool Continuous = false外部开关，由 Game 脚本控制：开始游戏前不刷食物，开始了才刷。
(int)Random.​Range(f1,​ f2)float 版 Range 再强转 int。这里是截断取整（去掉小数），不是四舍五入。注意：(int)3.9 = 3，要四舍五入得用 Mathf.RoundToInt。
borderLeft.​position.​x + 0.​5f加 0.5 留边距，防止食物生成在边界正上被吃掉或卡住。这个“±0.5”是设计细节，考设计题时可以提。
new Vector3(x,​ y,​ -0.​5f)Z 固定 -0.5，让食物在蛇所在的平面上（蛇头 Z = -0.6，食物略靠前一点，保证能被吃掉）。
考点：随机数的两个版本
Random.Range(int, int) → int，右端不含
Random.Range(float, float) → float，右端含
这里取 (int) 强转，属于「先用 float 版再用 int 截断」，和直接用 int 版不等价（int 版是均匀取整，float 版截断会让分布略微偏向小的数）。
为什么用 InvokeRepeating 而不是在 Update 里计时？
因为 InvokeRepeating 由引擎统一调度，不用自己维护计时变量，代码更短。
缺点：停止不方便（要 CancelInvoke("Spawn")），且方法名用字符串没有编译期检查。
设计题里问“为什么不用 Update 硬刷”就是考这个 —— 事件驱动优于轮询。

B7 · Player —— 台球主球的受力移动与进洞重置实验三 · 内容.doc
public class Player : MonoBehaviour {

    public float m_Force = 20;

    void Update() {
        float x = Input.GetAxis("Horizontal");
        float y = Input.GetAxis("Vertical");
        this.gameObject.GetComponent<Rigidbody>().AddForce(new Vector3(x, 0, y) * m_Force);
    }

    void OnCollisionEnter(Collision other) {
        if (other.collider.tag.Equals("Hole")) {
            Rigidbody rg = gameObject.GetComponent<Rigidbody>();
            rg.Sleep();
            gameObject.transform.position = new Vector3(0, 0.5f, 0);
        }
    }
}
代码作用
m_Forcem_ 前缀是匈牙利命名法（m = member，成员变量）。老师四个实验里都在用：m_Force、m_BallID、m_audiosource、m_ballPrefab。
AddForce(new Vector3(x,​ 0,​ y) * m_Force)Y 传 0，因为台球在地面上移动，不能往上推。X 和 Y 输入映射到 X 和 Z 轴——这是 3D 场景里「平面移动」的标准写法。
this.​gameObject.​GetComponent​<Rigidbody>()每帧 GetComponent，非常浪费。正确做法是在 Start 里缓存成字段（像课件 A11 的 rd 那样）。
other.​collider.​tag.​Equals("Hole")注意这里用 other.collider，不是 other.gameObject。两者都能取到 tag，collider 少一层跳转。
rg.​Sleep()让刚体休眠：速度归零、停止物理计算。如果不加这一句，重置位置后球还会带着原来的速度继续滚。
gameObject.​transform.​position = new Vector3(0,​ 0.​5f,​ 0);重置到原点。Y = 0.5 是因为球的半径是 0.5，放在 0 会陷进桌面。这个 0.5 是很容易考的细节。
★ Sleep() 和 WakeUp() 是必背的一对：
Sleep()　刚体休眠，静止不动，省性能
WakeUp() 唤醒刚体
为什么重置位置前要 Sleep？因为直接改 position 不会清速度，球会「带着旧速度瞬移」，看起来像弹飞。Sleep 就是清速度。
这段代码的顺序很讲究：先 Sleep() 再改 position。反过来就失效——先改位置，物理引擎下一帧还会用旧速度继续推它。

public class BallCreate : MonoBehaviour {

    public Transform m_ballPrefab;    // 预制小球，拖拽小球预制到变量中

    // 材质名称
    private string[] m_mid = new string[] { "ball1", "ball2", "ball3", "ball4", "ball5", "ball6" };

    private Vector3[] m_pos = new Vector3[] {
        new Vector3(0,     0.5f, 5),  new Vector3(0.5f,  0.5f, 6),
        new Vector3(-0.5f, 0.5f, 6),  new Vector3(1,     0.5f, 7),
        new Vector3(0,     0.5f, 7),  new Vector3(-1,    0.5f, 7)
    };

        for (i = 0; i < 6; i++) {
            Transform go = Instantiate(m_ballPrefab);
            go.transform.parent = this.gameObject.transform;
            go.position = m_pos[i];
            go.rotation = transform.rotation;
        }

        // 获取小球组
        GameObject[] balls = GameObject.FindGameObjectsWithTag("TargetBall");
        Material[] mats = new Material[balls.Length];

        for (i = 0; i < balls.Length; i++) {
            // 材质获取
            mats[i] = Resources.Load("Materials/" + m_mid[i]) as Material;

            // 设置小球 ID 和材质
            Ball ball = balls[i].GetComponent<Ball>();
            ball.m_BallID = i + 1;
            ball.GetComponent<MeshRenderer>().material = mats[i];
        }
    }

代码作用
Instantiate(m_ballPrefab)单参数版：只给预制体，位置和旋转沿用预制体自身的设定。和实验一的 Instantiate(prefab, pos, rot) 三参数版对比记。
Transform go = Instantiate(m_ballPrefab);返回值是 Transform，因为 m_ballPrefab 声明成了 Transform。如果声明成 GameObject，返回的就是 GameObject。
go.​transform.​parent = this.​gameObject.​transform;设置父物体（也可以用 go.SetParent(...)）。作用是让所有小球挂在一个空物体下，层次面板干净。
go.​position = m_pos[i];按数组里预设好的六个坐标依次摆放，形成台球的三角形摆法。
GameObject.​FindGameObjectsWithTag("TargetBall")复数版，返回所有 tag 为 TargetBall 的物体数组。注意方法名有 s：FindGameObjectsWithTag。
Resources.​Load("Materials/" + m_mid[i]) as Material字符串拼接路径，依次加载 ball1~ball6 六个材质。
ball.​GetComponent​<MeshRenderer>().​material = mats[i]改的是 material（单数）不是 sharedMaterial。这里故意用 material：每颗球要独立的材质实例，改一颗不影响其他颗。
这个 material / sharedMaterial 的取舍是必考点。
ball.​m_BallID = i + 1;ID 从 1 开始（i 从 0 开始，所以 +1）。
★ material vs sharedMaterial（极易考）
renderer.material　读的时候会自动复制一份新材质，改它只影响自己；写的时候也会创建实例。会打破批处理，慎用。
renderer.sharedMaterial　直接拿共享材质，改了所有用这个材质的东西一起变。
规律：要“各管各的”用 material，要“批量改”用 sharedMaterial。
这里六颗球要不同颜色，必须用 material。
这段最妙的一行是 go.transform.parent = ... 之前没写 go.position。先设父物体再设位置：因为设父物体时子物体位置会按父物体的坐标系重新解释，如果先设位置再设父物体，最终位置会偏。这个顺序坑很值得说。

public class BaseController : MonoBehaviour {

    public float FloWalkingSpeed  = 0.02F;   // 走路速度
    public float FloRatationSpeed = 0.2F;    // 旋转速度（Rotation 拼错成 Ratation）
    private Animator AnimaObj;               // 动画

    void Start() {
        AnimaObj = this.GetComponent<Animator>();

                AnimaObj.SetBool("IsRun", false);
                AnimaObj.SetFloat("Speed", 1);
            }

        }
        else if (Input.GetKey(KeyCode.S)) {
            this.transform.Translate(Vector3.back * FloWalkingSpeed);
        }
        else {
            AnimaObj.SetFloat("Speed", 0);
            AnimaObj.SetBool("IsRun", false);
        }

        // 转弯
        if (Input.GetKey(KeyCode.A)) {
            this.transform.Rotate(Vector3.down * FloRatationSpeed);
        }
        else if (Input.GetKey(KeyCode.D)) {
            this.transform.Rotate(Vector3.up * FloRatationSpeed);
        }
    }
}
代码作用
Input.​GetKey(KeyCode.​W)按住 W 的每一帧都返回 true，所以能连续前进。用 GetKeyDown 就只能走一步。
Input.​GetKey(KeyCode.​LeftShift)按 Shift 切奔跑。注意 KeyCode 名是 LeftShift，写 Shift 不存在。
AnimaObj.​SetBool("IsRun",​ true)参数名必须和状态机里大小写完全一致。
AnimaObj.​SetFloat("Speed",​ 1)Speed = 1，对应状态转移条件 Speed > 0.1，所以会进入 Walking。
this.​transform.​Translate(Vector3.​forward * FloWalkingSpeed)没乘 deltaTime，所以速度跟帧率挂钩。FloWalkingSpeed = 0.02 就是按「一帧挪 0.02」来定的，60fps 下大约 1.2 单位/秒。课件的写法，不要学。
transform.​Rotate(Vector3.​down * FloRatationSpeed)A 键用 Vector3.down（−Y 轴）→ 向左转。D 键用 Vector3.up（+Y 轴）→ 向右转。这里 Vector3.up/down 被当轴用，每帧转 0.2 度。
else { SetFloat("Speed",​ 0); .​.​.​ }没有按 W 就回站立。注意这个 else 是跟 if (W) 配对的，S 的分支走到这里会设 Speed=0（也就是倒着走时播放站立动画 —— 课件的小 bug）。
★ Rotate(Vector3.up * x) 和 Rotate(0, x, 0) 的区别
Rotate(Vector3.up * 0.2f)　→ 两个参数：第一个被当成欧拉角，所以这是「绕 Y 转 0.2 度」
Rotate(0, 0.2f, 0)　→ 三个参数：三个欧拉角分量，效果完全一样
Rotate(Vector3.up, 0.2f)　→ 两个参数但第二个是 float：这是「绕 up 轴转 0.2 度」，结果也一样
三种写法在这个场景结果相同，但参数含义不同 —— 这是最容易出选择题的地方。
实验四代码里的一个真 bug：按 W 时，if/else 分支里都设了 IsRun，但 else 分支（走路）设了 Speed = 1 而 if 分支（跑步）没设 Speed。所以从走路切到跑步时 Speed 会停留在 1，状态机可能不会切到 Running。答辩时指出这点很加分。
B12 · Blendtree —— 融合树双参数控制实验四 · 内容.doc
public class Blendtree : MonoBehaviour {

    public float forwardSpeed = 7.0f;    // 前进的速度
    public float rotateSpeed  = 2.0f;    // 身体旋转速度
    private Animator anim;

    void Start() {
        anim = GetComponent<Animator>();
    }

    void Update() {
        // 旋转
        float h = Input.GetAxis("Horizontal");
        anim.SetFloat("Direction", h);
        transform.Rotate(0, h * rotateSpeed, 0);

        // 前进
        if (Input.GetKey(KeyCode.UpArrow)) {
            if (Input.GetKey(KeyCode.Z)) {
                anim.SetFloat("Speed", 1f);      // running
                forwardSpeed = 3f;
            }
            else {
                anim.SetFloat("Speed", 0.5f);    // walking
                forwardSpeed = 1;
            }
            transform.Translate(Vector3.forward * forwardSpeed * Time.deltaTime);
        }
        else {
            anim.SetFloat("Speed", 0f);
        }
    }
}
代码作用
Input.​GetAxis("Horizontal")返回 -1~1 的连续值（带平滑），所以 Direction 参数能取 0.37 这种中间值 —— 这正是融合树需要的。
anim.​SetFloat("Direction",​ h)把 -1~1 直接喂给融合树的一个轴，融合树就会在 左(-1)/中(0)/右(1) 三个动作之间插值。
anim.​SetFloat("Speed",​ 0.​5f)0.5 = 走，对应融合树里 walking 的临界点 0。1 = 跑，对应 run 的临界点 0.8。所以 0.5 落在 walking 区间、1 落在 run 区间。
anim.​SetFloat("Speed",​ 0f)没按前进键 → Speed 归零 → 播放站立（Standing 的转移条件是 Speed < 0.1）。
forwardSpeed = 3f; / = 1;代码里改的是对象自身的移动速度，和动画参数是两套独立的东西——一个控制「看起来在跑」，一个控制「实际跑多快」。两者要手动对齐，这是常见的“滑步”来源。
transform.​Translate(Vector3.​forward * forwardSpeed * Time.​deltaTime)这一行是标准的：乘了 deltaTime，速度和帧率无关。
★ 融合树的三个数值要记（实验四 4-6 步）
walking 子节点临界点：Direction = −1 / 0 / 1（左 / 中 / 右）
run 子节点临界点：Direction = −1 / 0 / 1
Motion 层两个子节点：walking = 0，run = 0.8，参数是 Speed
所以 Speed = 0.5 走、Speed = 1 跑，都是相对这两个临界点算的。
「滑步（foot sliding）」是什么：动画里角色迈步的速度和它在场景里实际移动的速度不一致，看起来像脚在地上打滑。
解决办法：把 forwardSpeed 和动画的 Speed 参数绑定，或者用 Animator 的 root motion（由动画驱动位移，而不是代码驱动）。这是设计题/答辩的加分点。

骨架 10　对象池（课设和设计题的高频答案）

public class SimplePool : MonoBehaviour {
    public GameObject prefab;
    private Queue<GameObject> pool = new Queue<GameObject>();

    public GameObject Get() {
        if (pool.Count > 0) {
            GameObject go = pool.Dequeue();
            go.SetActive(true);
            return go;
        }
        return Instantiate(prefab);
    }

    public void Return(GameObject go) {
        go.SetActive(false);
        pool.Enqueue(go);
    }
}
对象池为什么重要：反复 Instantiate + Destroy 会产生大量内存垃圾，触发 GC（垃圾回收）时游戏会卡顿。对象池的思路是「不销毁，只隐藏，下次复用」。这是游戏设计题的标准答案之一，问「怎么优化频繁生成销毁的物体」就答它。
