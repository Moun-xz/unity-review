1-1假如你是《王者荣耀》的美工，需要掌握哪些技能和技术6 分

身份：一款日活过亿的 MOBA 手游的美工。
需要说清：这个岗位要做哪些活、会哪些工具、懂哪些引擎里的规矩。

我会把美工的能力拆成三块来讲：做资源的能力、落地的能力、协作与优化的能力。只会做资源、不懂落地，资源进引擎就变形；只懂落地、不会做资源，只能做二次加工，做不出原创。

一、美术资源制作

  • 建模：用 3ds Max / Maya / Blender，掌握多边形建模、布线、UV 拆分。手游对面数预算要求严格，一个英雄主体通常控制在万面以内，所以要做低模 + 法线烘焙，而不是靠堆面数。
  • 贴图：用 Photoshop / Substance Painter 绘制 Albedo（固有色）、Normal Map（法线）、Roughness（粗糙度）、Metallic（金属度）。
  • 骨骼与动画：绑定骨骼、刷权重、制作待机/行走/技能动作，导出 FBX。人形角色统一走人形骨骼（Humanoid），方便动画复用到不同英雄上。
  • UI 与特效：绘制 UI 切图（按钮、图标、血条底图），制作技能特效的序列帧或粒子贴图。

二、在 Unity 里落地

  • 导入设置：模型导入后生成 Avatar；贴图设为 Sprite 或 Default，勾选压缩格式（安卓用 ASTC / ETC2），开 mipmap 供远距离显示。
  • 材质与 Shader：理解 纹理 → 材质 → Shader 三层关系。纹理是原始图片，材质是参数的组合，Shader 是渲染规则。同一个 Shader 换不同参数，就是一个新材质——这是做皮肤换色的基础。
  • 光照：静态场景用烘焙（Lightmap）保证质感，动态角色用 Light Probe 采样环境光，才不会出现角色走进阴影里还发亮的穿帮。

三、协作与优化

  • 命名与目录规范：按 角色/场景/UI/特效 分目录，统一前缀，让程序能靠名字找到资源。
  • 图集（Atlas）：同屏多张 UI 图打进一张图集，减少 Draw Call。
  • LOD：远景模型换成低面数版本，节省渲染开销。
  • 性能预算意识：做资源时就要知道这块资源占了多大的内存和渲染开销，而不是做完再交给程序去优化。
六个得分点
  • 说清美工不只是「画画」，是资源制作 + 引擎落地 + 优化协作三块
  • 点出贴图种类：Albedo / Normal / Roughness / Metallic
  • 点出引擎关系：纹理 → 材质 → Shader 三层
  • 点出面数预算与低模 + 法线烘焙的思路
  • 点出图集、LOD、Draw Call 三个优化手段
  • 最后一句落到「为性能服务」，体现你不是只会画图

1-2枪战游戏中，枪口的烟火、烟雾以及击中特效怎么实现6 分

三个效果：枪口火焰、枪口烟雾、击中特效。
要求：说清用什么技术、各调哪几个模块、为什么这么调。

三个效果都用 Particle System（粒子系统）做，区别在于参数配置。粒子系统的本质是「用大量小面片模拟不规则、易消散的现象」——火焰、烟雾、火花都是这种特征，用模型做不出来，用动画帧则太占资源。

① 枪口火焰：短、亮、一次

  • Duration 设 0.1 秒左右，Looping 取消——它只该闪一帧到三帧
  • Emission 用 Burst 一次性喷 8~15 个粒子，不用 Rate over Time 持续发射
  • Shape 选 Cone（圆锥），角度开小，朝枪口正前方喷
  • Color over Lifetime：从白 → 橙 → 透明，模拟温度衰减
  • Size over Lifetime：快速缩小到 0
  • Renderer：材质用 Additive（叠加）混合模式，才会有发光感；勾 Billboard 让粒子始终面向相机

② 枪口烟雾：慢、淡、飘

  • Duration 拉长到 0.5~1 秒，Size over Lifetime 反过来由小变大
  • Color over Lifetime 的 Alpha 渐隐到 0，这是烟雾消散的关键
  • Velocity over Lifetime 给一点向上的漂移，加 Noise（噪波）模块让它不规则地翻滚
  • 材质用 Alpha Blend（半透明），不用 Additive——烟雾是遮挡光，不是发光

③ 击中特效：在碰撞点生成

  • 用射线检测（Raycast）拿到命中点与法线，在该点 Instantiate 特效预制体
  • 火花的 Renderer 用 Stretched Billboard，按速度方向拉长成条状，看起来才有速度感
  • 用 Sub Emitters：主粒子（火花）死亡时触发二级粒子（碎屑、烟），一次配置出复合效果
  • 特效朝向对齐命中面的法线，贴墙和贴地才不会穿模

④ 三个工程细节（拉分的地方）

  • 用一个预制体 + 对象池：开枪频率高，不能每次 Instantiate 再 Destroy，改成从池里取、播完 SetActive(false) 还回去
  • 单个粒子系统用 Play() / Stop() 控制；复合特效（火光 + 烟 + 火花组成一个物体）要用整个 GameObject 的 SetActive() 开关——这是课件 06 明确区分的两种情况
  • 性能取舍：同屏粒子数设上限（Max Particles），远处特效降频或直接不生成
六个得分点
  • 答出技术名：Particle System 粒子系统
  • 答出至少四个模块名：Emission / Shape / Color over Lifetime / Size over Lifetime / Renderer / Sub Emitters
  • 火焰用 Burst 一次性发射，不是持续发射
  • 火焰用 Additive、烟雾用 Alpha Blend（这一条最能体现你真调过）
  • 击中特效靠 Raycast 拿命中点再生成
  • 收尾提对象池与 Play/Stop 与 SetActive 的区别
课件原话可引（Game 06）：over Lifetime 类模块「类似花开花落的一生」，by Speed 类「类似跑龙套」；单个粒子用 Play/Stop，复合粒子 GameObject 用 SetActive。

1-3动画系统的融合树，在游戏中哪些动画中体现，具体如何实现6 分

两问：用在哪些动画上（举例）+ 怎么实现（步骤与参数）。

先给一句定性：动画混合树在动画状态机中是一个特殊类型的状态，它内部不靠状态切换，而是靠一个数值参数连续混合多个动作。所以它解决的是「同一个动作在不同强度之间平滑变化」的问题，不是「不同动作之间切换」的问题。

一、游戏里哪些动画会用融合树

场景说明
走 ↔ 跑最典型。速度从 0 连续加到 10，动作从走过渡到跑，中间自动生成半走半跑的姿态，不会硬切
转向左转走、直走、右转走三套动作，用一个 direction 参数在 −1~1 之间混合
瞄准姿态上身竖直 / 侧身 / 蹲姿之间按瞄准角度混合，常配合动画层使用
受伤程度轻伤、重伤两套待机，按血量比例混合，血越少动作越踉跄
坡度适配上坡、平地、下坡三套走姿，按地形坡度混合（2D Blend Tree）

二、怎么实现（以「走跑切换」为例）

  1. 参数必须用 Float。在 Animator 面板新建参数 Speed，类型选 Float。Bool 只有真假两态，做不出 0.5 这种中间值，混合就没有过渡。
  2. 建树：在 Animator 里右键 Create State → From New Blend Tree，双击进去，把 walking、running 两个动画拖进 Blend Tree，Blend Type 选 1D。
  3. 设临界点：walking 设 0、running 设 0.8。参数为 0 时是走，0.8 时是跑，中间按比例混合。
  4. 要做两层结构：外层一个 Speed 参数混合「走树」和「跑树」；每棵子树内部再放 walkingleft / walking / walkingright 三个动作，用 direction 参数混合，临界点 −1、0、1。
  5. 改不动临界点怎么办：先取消勾选 Automate Threshold，手动填写数字，填完再勾回去。直接拖是拖不动的。
  6. 代码里赋值：anim.SetFloat("Speed", 0.9f);，数值要和角色实际移动速度同步，否则会出现「腿在飞奔、人却挪得慢」的滑步。

三、一条必须记住的限制

「为了使混合过后的动作起作用，必须混合造型和时间相近的动作」——这是课件原话。所以走和走的变体可以放一棵树，跑和跑的变体放另一棵树，但不能把走和跑混在同一棵树里：它们的步幅和周期差太多，混出来会像原地抽搐。

六个得分点
  • 开头给出定义：融合树是动画状态机中的一种特殊类型的状态（课件原话）
  • 举例至少两个：走跑切换、转向（或瞄准、受伤、坡度）
  • 参数类型必须 Float，并说明为什么不能用 Bool
  • 给出临界点数值（0 和 0.8，或 −1 / 0 / 1）
  • 提到 Automate Threshold 要先取消勾选才能改
  • 引用限制：只能混合造型和时间相近的动作

1-4游戏场景中的工厂、密闭环境，如何实现得更加逼真6 分

场景：室内工厂、密闭空间。
关键词：逼真。要答的是用什么手段做出真实感，不是「多放几个模型」。

密闭环境的真实感来自三件事：光要对、暗部要有细节、空气里要有东西。工厂这种场景真正的难点不是建模，是「没有天光」——全靠人造光源，光一错，整个空间就假。

一、光照：这是主战场

  • 主体光用烘焙。工厂的天窗、厂房、管道都不会动，属于静态物体，把它们勾上 Static，方向光 Mode 设 Mixed，用 Baked Lightmap 烘焙。
  • 顶灯用 Spot Light（聚光灯），模拟厂房高处的工矿灯，配一个向下的 Cookie 投出灯罩的形状。Spot 的 Range 和 Spot Angle 决定光锥，Intensity 决定亮度。
  • 局部光源用 Point Light，做机器指示灯、仪表盘、角落的应急灯。
  • 柔和的面光用 Area Light。课件原话：区域光无法用作实时光照，必须烘焙，物体必须静态，用于建立柔和的照明效果——高窗透进来的漫射光正好用它。
  • 阴影：主光开 Soft Shadows（软阴影，真实但耗性能），次要光源用 Hard Shadows 或干脆关掉。注意 Bias 不能太小，否则物体表面会出现 self-shadow 的黑斑。

二、材质与细节：让表面「不平」

  • 法线贴图（Normal Map）：金属板、砖墙、混凝土地面的凹凸全靠它。实时渲染的多边形预算有限，用贴图做出表面细节，性价比远高于堆高模。
  • 粗糙度贴图：工厂里油污、水渍、锈迹的反射程度不一样，靠 Roughness 贴图区分，才会「有的地方反光、有的地方发哑」。
  • 贴花（Decal）：油渍、划痕、警示标线用贴花投在表面，比做进模型里灵活得多。

三、空气感：密闭空间最缺这一层

  • 雾效（Fog）：开启指数雾，给一点灰白色。工厂里空气不干净，远处会被雾「吃掉」，纵深立刻出来。
  • 粒子做悬浮物：细微的灰尘、蒸汽、管道漏气，用一个低发射率的粒子系统持续飘。
  • 体积光（Volumetric Light）：从高窗斜射进来的光柱，这是室内场景最出效果的一笔。

四、动态物体的处理

玩家和可移动的机械不能烘焙，把它们的 Static 勾掉走实时光照，同时在场景里布 Light Probe（灯光探测器），让动态物体从最近的探针插值出环境光。这样角色走进暗角会变暗，走进灯下会变亮，光影是连贯的。

六个得分点
  • 点出密闭环境的核心难点：没有人造天光，全靠人造光源
  • 答出光源类型分工：Spot 顶灯 / Point 局部 / Area 柔和面光
  • 答出 Area Light 不能实时光照、必须烘焙、物体必须静态
  • 答出烘焙流程关键词：Static 勾选 + Mixed + Generate Lighting
  • 答出 法线贴图做表面凹凸、雾效做空气感
  • 答出 Light Probe 解决动态物体光照——这一条是分水岭

1-5地形中这六个按键的作用6 分

截图是 Terrain 组件的笔刷下拉菜单，六项：
Set Height　Smooth Height　Paint Texture　Paint Holes　Stamp Terrain　Raise or Lower Terrain

这六个是地形组件的笔刷工具，用来在同一个地形上做出高度、纹理、洞口。它们不是并列的六个功能，而是塑形 → 修饰 → 贴图 → 挖洞 → 压模这样一条操作链上的不同环节。

工具中文作用
Raise or Lower Terrain升高/降低 最基础的塑形笔刷。按住左键升高、按住 Shift 降低，用笔刷形状一块块堆出山丘和洼地。地形造型的第一道工序。
Set Height设定高度 把笔刷范围内的地形一次性压平到某个绝对高度。用来做平台、台地、断崖的顶面——同一片区域刷完，高度完全一致，这是 Raise 做不到的。
Smooth Height平滑高度 抹平棱角。Raise 堆出来的山往往很尖，用平滑笔刷来回刷几遍，就变成自然的缓坡。也可能用来做河床、道路的过渡。
Paint Texture绘制纹理 画地表贴图。要先点 Create Layer 添加纹理层（草地、岩石、沙土、雪），然后用笔刷在不同层之间涂——涂到哪块，那块就显示对应的地表。这是地形「看起来像什么」的关键。
Paint Holes绘制洞 在地形上打洞，直接挖穿。用来做洞穴入口、地下室、竖井。注意它挖的是「洞」，不是「坑」——用 Raise 做出来的是凹下去的坑，Paint Holes 是真正穿透。
Stamp Terrain印章 用一张笔刷图案整体压印地形。相当于把预置好的形状（山峰群、丘陵群）像盖章一样压到地形上，适合快速做出一片有规律的起伏，比一笔一笔刷快得多。

实际制作时的顺序

通常是：Raise or Lower 做大体起伏 → Set Height 压平台地 → Smooth Height 修顺坡面 → Stamp Terrain 批量压出丘陵群 → Paint Texture 分层上地表 → Paint Holes 挖洞口。先塑形后贴图，因为贴图是按高度和坡度分布的，形没定好就贴，后面改形还得重贴。

六个得分点（一项一分，能全写上就满）
  • Raise or Lower：基础塑形，堆山挖坑，按 Shift 反向
  • Set Height：压到指定绝对高度，做平台、台地
  • Smooth Height：平滑棱角，做自然缓坡
  • Paint Texture：先 Create Layer 再加层，绘制地表贴图
  • Paint Holes：挖穿地形，做洞口、地下室
  • Stamp Terrain：用图案整体压印，批量塑形
答题技巧：这题不用写长，但要一项一句、六个都写。写四项只能拿 4 分，漏掉的两个往往就是最不常用的 Stamp Terrain 和 Paint Holes。最后补一句「先塑形后贴图」的顺序，是加分项。

2-1台球蓄力击打15 分

场景：实验三 台球。鼠标按住蓄力，松开击球，力度用 UI 显示。
考点集中在：输入、蓄力累加、限幅、施加冲量、UI 显示、物理时序。

这道题会挖的 7 个空（按可能性排序）

序答案判断依据
1GetMouseButtonDown按下的一瞬间开始蓄力。要用 Down 不是 GetMouseButton，后者按住每帧都返回 true，蓄力会被反复重置
2GetMouseButtonUp松开的一瞬间击球。同理要用 Up，只触发一次
3Time.deltaTime蓄力值累加：power += chargeSpeed * Time.deltaTime。不乘就是「每帧加多少」，帧率一高就瞬间满了
4Mathf.Clamp把蓄力限制在 0~1（或 0~maxForce）。不限幅，一直按住就爆表，打出去的球会飞出天际
5AddForce给球施加力。rb.AddForce(dir * power, ForceMode.Impulse)
6ImpulseForceMode 选 Impulse（冲量）。台球是一击脱手，不是持续推——用 Force 会变成「一直推着球走」，用 VelocityChange 则忽略质量
7fixedDeltaTime 或 FixedUpdate物理相关写在 FixedUpdate 里，用 Time.fixedDeltaTime

其他可能出现的空

API用在哪
Raycast / ScreenPointToRay鼠标点击选中球体：把屏幕坐标转成射线，打中哪个球就操作哪个
GetComponent<Rigidbody>()拿到刚体才能加力
fillAmount蓄力条：Image 的 ImageType 设「过滤填充」，改 fillAmount（0~1）显示力度
slider.value另一种做法：用 Slider 显示力度，删掉 Handle 就是一根血条式的力度条
normalized方向向量单位化，只留方向不要长度
velocity读球的速度，判断是否停下（小于阈值就允许再次击打）

参考实现

public Rigidbody rb;
public Image powerBar;
public float chargeSpeed = 1.2f;
public float maxForce = 15f;
private float power = 0f;
private bool charging = false;

void Update(){
    // 按下开始蓄力
    if (Input.(1)(0)) { charging = true; power = 0f; }

    // 蓄力中累加，并限幅
    if (charging) {
        power += chargeSpeed * Time.(3);
        power = Mathf.(4)(power, 0f, 1f);
        powerBar.fillAmount = power;
    }

    // 松开击球
    if (Input.(2)(0) && charging) {
        charging = false;
        Vector3 dir = Camera.main.transform.forward.normalized;
        rb.(5)(dir * power * maxForce, ForceMode.(6));
        powerBar.fillAmount = 0f;
    }
}
四个真正的考点
  • Down / Up 与「按住」的区别：蓄力必须用一次性事件，不能用持续检测
  • 乘 deltaTime：蓄力是「每秒加多少」，必须与帧率解耦
  • Clamp 限幅：不限幅一定会爆表
  • ForceMode.Impulse：一击脱手用冲量，不是持续力

2-2UI 中的两个 Toggle 组件控制声音的播放15 分

场景：实验四 unitychan 的设置面板。两个 Toggle，一个控制背景音乐，一个控制音效。
考点集中在：Toggle 的取值、事件绑定、AudioSource 属性、跨场景保存。

这道题会挖的 8 个空

序答案判断依据
1isOn读 Toggle 当前状态。不是 value、不是 checked——UGUI 的 Toggle 用 isOn
2onValueChanged状态变化时的事件，用 AddListener 挂方法
3AddListenertoggle.onValueChanged.AddListener(方法)。注意方法要带 bool 参数（Toggle 传过来的是新值）
4mute静音开关，最直接：audioSource.mute = !on
5volume调音量 0~1，可做渐弱：audioSource.volume = on ? 1f : 0f
6Play / PlayOneShot打开音效时播放：BGM 用 Play()，短音效用 PlayOneShot()（可叠加、不打断）
7PlayerPrefs保存设置：PlayerPrefs.SetInt / GetInt，下次进游戏还记着
8AudioListener.volume全局音量（范围 0~1），一次改所有声音

参考实现

public Toggle bgmToggle;
public Toggle sfxToggle;
public AudioSource bgmSource;
public AudioSource sfxSource;

void Start(){
    // 读档，默认开着是 true
    bgmToggle.isOn = PlayerPrefs.GetInt("BGM", 1) == 1;
    sfxToggle.isOn = PlayerPrefs.GetInt("SFX", 1) == 1;

    // 绑定事件（方法必须带 bool 参数）
    bgmToggle.(2).(3)(OnBgmChanged);
    sfxToggle.onValueChanged.AddListener(OnSfxChanged);
}

void OnBgmChanged(bool on){
    bgmSource.(5) = on ? 1f : 0f;
    if (on && !bgmSource.isPlaying) bgmSource.(6)();
    PlayerPrefs.SetInt("BGM", on ? 1 : 0);
}

void OnSfxChanged(bool on){
    sfxSource.(4) = !on;
    PlayerPrefs.SetInt("SFX", on ? 1 : 0);
}

三个容易错的地方

  • 监听方法的签名必须是 void 方法名(bool)。写成无参方法不会报编译错，但运行时会抛异常或者根本不响应——这是最常踩的坑。
  • isOn 不是 value。Slider 用 value，Toggle 用 isOn，两个控件的属性名不同，很容易填混。
  • BGM 的 AudioSource 必须把 Spatial Blend 拖到 2D（0）。背景音乐不随位置衰减，用 3D 会让它跟着相机距离忽大忽小。
四个真正的考点
  • isOn：Toggle 的状态属性名
  • onValueChanged.AddListener：事件绑定，方法带 bool 参数
  • mute / volume 二选一：静音用 mute，渐弱用 volume
  • Play 与 PlayOneShot 的区别：Play 会打断，PlayOneShot 可叠加

3-1防御塔守基地10 分 · 3 小问

敌人从出生点沿路线走向基地，玩家在路旁放置防御塔攻击敌人，敌人死亡后掉金币。3D 场景。
(1) 用到哪些预制体
(2) 如何实现敌人沿固定路径移动，以及防御塔如何攻击敌人
(3) 敌人脚本 enemy.cs 的业务逻辑

(1) 预制体清单（4 分）

这个游戏里「会被反复创建」的东西，都应该做成预制体：

预制体说明
防御塔包含塔基、炮塔、射程指示圈。炮塔要能单独旋转，所以和塔基分成父子节点
敌人含模型、碰撞体、Animator、状态机脚本
子弹 / 弹丸塔生成的攻击物，含 Rigidbody + Collider（勾 Is Trigger）+ 命中特效
金币敌人死亡时掉落，Collider 勾 Is Trigger，玩家走过自动拾取
死亡特效粒子预制体，敌人死亡时在尸体位置播放
血条敌人头顶的血条（世界空间 Canvas 或 Quad），随敌人移动
路径点空物体，只用来标记路线拐点

(2) 固定路径 + 塔的攻击（3 分）

固定路径有两种做法，二选一写清即可：

  • Waypoint 路径点法：把路径点按顺序存进一个 List<Transform>，敌人每帧朝 waypoints[index] 走，用 Vector3.MoveTowards 或 transform.Translate；走到距离小于阈值就 index++，走到最后一个点就算到达基地。
  • NavMesh 寻路法：把整片地形烘成 NavMesh，敌人挂 NavMeshAgent，每帧 agent.SetDestination(当前路点)，靠寻路算法自动绕开障碍。

塔的攻击流程，四步：

  1. 找目标：用 Physics.OverlapSphere(塔位置, 攻击半径, 敌人层掩码) 一次查出范围内所有敌人，不要遍历全场景
  2. 选目标：按离塔最近、或血量最低、或最靠近基地来排序——这是玩法设计的一部分，写清你的选择
  3. 转向：Quaternion.LookRotation(目标 - 塔) 算出朝向，再用 Quaternion.Slerp 平滑转过去，不要一帧硬转
  4. 开火：冷却计时（cd -= Time.deltaTime）到 0 就生成子弹，子弹命中后给敌人扣血；子弹同样走对象池

(3) enemy.cs 的业务逻辑（3 分）

面试式答法：说清这个脚本管什么、不管什么。

public class Enemy : MonoBehaviour
{
    public float maxHp = 100f;      // 血量
    public float moveSpeed = 2f;    // 移动速度
    public int reward = 10;         // 死亡掉落金币数
    public GameObject coinPrefab;   // 金币预制体
    private float hp;
    private int index = 0;          // 当前走到第几个路点

    void Start(){ hp = maxHp; }

    void Update(){
        // ① 沿路点移动
        MoveAlongPath();
    }

    // ② 受击：外部只能通过这个方法扣血
    public void TakeDamage(float dmg){
        hp -= dmg;
        if (hp <= 0) Die();
    }

    // ③ 死亡：掉金币、播特效、回收进池
    void Die(){
        GameManager.Instance.AddCoin(reward);       // 或掉落金币预制体
        Instantiate(coinPrefab, transform.position, Quaternion.identity);
        GameManager.Instance.OnEnemyDead(this);
        PoolManager.Instance.Return(gameObject);     // 对象池回收，不 Destroy
    }

    // ④ 走到终点：扣基地血量
    void ReachBase(){
        GameManager.Instance.DamageBase(1);
        PoolManager.Instance.Return(gameObject);
    }
}

要点：血量私有、只能通过 TakeDamage 改；死亡不 Destroy 而是还给对象池；金币既可以Instantiate实体掉落，也可以直接加数值——后者性能更好，前者更有反馈感，答的时候说明你的取舍。

得分点
  • (1) 预制体至少写五个，含塔、敌人、子弹、金币、特效；金币要提到 Is Trigger
  • (2) 路径写 Waypoint 数组 + 索引递增或 NavMeshAgent；攻击写 OverlapSphere 找目标 + 冷却 + 生成子弹
  • (2) 提到转向用 LookRotation + Slerp，不是瞬间对准
  • (3) 业务逻辑覆盖移动、受击、死亡、到基地四件事，并提对象池

3-2敌人巡逻 / 追击 / 攻击三状态 + 玩家第一人称15 分 · 3 小问

玩家走进敌人的攻击范围，敌人有巡逻、追击、攻击三种状态。
(1) 玩家如何实现第一人称视角、视角转动，用到哪些组件
(2) 三种状态的切换条件
(3) 玩家脚本 player.cs 的业务逻辑

(1) 第一人称：移动和视角是两套东西（6 分）

部分用什么怎么做
移动 CharacterController
（或 Rigidbody + CapsuleCollider）		 读 GetAxis("Horizontal") 和 GetAxis("Vertical") 算方向，controller.Move(dir * speed * Time.deltaTime)。CharacterController 自带碰撞与爬坡，不用自己处理重力以外的物理
水平视角 转整个角色 Input.GetAxis("Mouse X") → transform.Rotate(0, mx * 灵敏度, 0)。人转身，相机跟着转
垂直视角 只转相机 Input.GetAxis("Mouse Y") → 累加到 xRotation 变量，Clamp 到 −90°~90°，再赋给相机的 localRotation

三个必须说的细节，正是这题的分数所在：

  1. 垂直只能转相机，不能转身体。身体跟着抬头的方向转，人就会整个翻过去，看到自己倒立的腿。
  2. 垂直角度必须 Clamp 在 ±90°。不卡住的话，鼠标一直往上甩，视角会越过头顶转到背后。
  3. 不能用 transform.localEulerAngles.x -= ... 直接改。欧拉角会自动回绕，转到 270 会突然跳回 90，表现为视角猛地一弹。要用一个 float xRotation 变量自己累加，再赋回去。

另外两个配套设置：Cursor.lockState = CursorLockMode.Locked; 把鼠标锁在窗口内，否则视角转到一半鼠标跑出屏幕；相机作为玩家的子物体，位置放在头部高度。

(2) 三种状态的切换条件（5 分）

用有限状态机（FSM）：一个枚举 enum EnemyState { Patrol, Chase, Attack }，四条转移，四个条件：

转移条件
巡逻 → 追击玩家进入视野半径（距离 < sightRange），或射线检测发现玩家
追击 → 攻击玩家进入攻击半径（距离 < attackRange）
攻击 → 追击玩家跑出攻击半径但仍在视野内
追击 → 巡逻丢失目标（距离 > 视野半径，或超出寻路范围）

实现上用 switch(state) 分派，或在状态切换时做进入/退出动作：进入 Attack 要 agent.isStopped = true 停下来，退出再恢复，否则敌人会边跑边打，动作和位移打架。不要写成一堆嵌套 if，敌人一多就没法维护。

(3) player.cs 的业务逻辑（4 分）

按「输入 → 移动 → 视角 → 状态 → 交互」五段说：

public class Player : MonoBehaviour
{
    public float moveSpeed = 5f;
    public float mouseSensitivity = 2f;
    public Transform cameraPivot;
    private CharacterController cc;
    private float xRotation = 0f;
    private float verticalSpeed = 0f;

    void Start(){
        cc = GetComponent<CharacterController>();
        Cursor.lockState = CursorLockMode.Locked;   // 锁鼠标
    }

    void Update(){
        Look();      // 视角
        Move();      // 移动
    }

    void Look(){
        float mx = Input.GetAxis("Mouse X") * mouseSensitivity;
        float my = Input.GetAxis("Mouse Y") * mouseSensitivity;

        transform.Rotate(0f, mx, 0f);              // 水平：转身体
        xRotation -= my;                            // 垂直：只转相机
        xRotation = Mathf.Clamp(xRotation, -90f, 90f);
        cameraPivot.localRotation = Quaternion.Euler(xRotation, 0f, 0f);
    }

    void Move(){
        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");
        Vector3 dir = transform.right * h + transform.forward * v;
        cc.Move(dir * moveSpeed * Time.deltaTime);
    }
}

业务逻辑还要补两点：重力（verticalSpeed += gravity * Time.deltaTime，再一起交给 cc.Move），以及与敌人的交互（进入敌人攻击范围时给玩家扣血 / 触发受击反馈）。

得分点
  • (1) 组件写 CharacterController + Camera（子物体），或 Rigidbody + Collider
  • (1) 水平转身体、垂直只转相机，这一句是核心
  • (1) 提 Clamp ±90° 和 Cursor.lockState
  • (2) 四条转移、四个条件写全，缺一条少一分
  • (2) 点出状态机的进入/退出动作（停/开寻路）
  • (3) player.cs 覆盖输入、移动、视角、重力四块
题干的一处说明：题目说「玩家走进敌人的攻击范围内，有三种状态」，但巡逻/追击/攻击是敌人的状态，不是玩家的。考试时按「敌人三状态 + 玩家第一人称」分开答就对了，不要被题干绕进去。

3-33D 无限跑酷15 分 · 含 4 小问

3D 无限跑酷游戏。
① 用到的预制体和组件
② 为什么不是一次性生成整个跑道资源，而是分段加入游戏场景
③ 玩家前进、左右移动怎么实现
④ 碰撞该选 Trigger 触发器还是普通碰撞体

① 预制体与组件（4 分）

对象预制体组件
玩家角色模型（含动画）CharacterController（或 Rigidbody + CapsuleCollider）、Animator、AudioSource；相机作为子物体跟随
跑道路块路块是最关键的预制体，每段等长，带障碍物槽位BoxCollider，不挂刚体（静态碰撞体）
障碍物栏杆、低墙、高墙、移动障碍BoxCollider，不挂刚体
可收集物金币、加速道具Collider 勾 Is Trigger
特效撞击火花、拾取光效Particle System

② 为什么分段加载（4 分，本题最重的一问）

核心原因是无限跑酷在时间上无限，而内存在物理上是有限的。四条理由，按重要性排：

  1. 内存不可能装下整条跑道。玩家可以一直往前跑，跑道理论上无限长；如果一次性生成全部路块，内存会持续增长直到崩溃。分段 + 循环复用让内存恒定在几段路块的大小。
  2. 性能与帧率。场景里的 GameObject 越多，渲染、物理、脚本的每帧开销越大。一次只保留玩家附近 5~8 段，远处的销毁或回收，同屏对象数固定，帧率才稳。
  3. 逻辑上根本不需要那么多。摄像机看得到的只有前方几十米，身后已经跑过的路段玩家再也看不见——生成出来纯属浪费。这是渲染的视野可见性原则。
  4. 玩法需要随机性。分段之后，每段路块的内容可以在生成时随机抽取（障碍物位置、金币分布），无限跑酷的重复可玩性就是靠这个。一次生成好就固定了，玩两遍就腻。

具体做法：对象池 + 循环复用。预先创建 8~10 段路块排成一条线；玩家每前进一段，把最后面那一段移动到最前面接上（transform.position 平移一个路块长度），并重新随机它的内容。这样全程不 Instantiate 也不 Destroy，没有 GC 卡顿，内存恒定。

这段话能拿满的关键：不要只说「节省内存」。要说出「无限 vs 有限」这个矛盾，并给出「对象池 + 路段循环复用」这个解法，再说一句「每段新生成时重新随机内容，保证可玩性」。

③ 前进与左右移动（4 分）

  • 自动前进：不用玩家按键。每帧 controller.Move(Vector3.forward * speed * Time.deltaTime)，速度随时间逐渐加快（speed += accel * Time.deltaTime）制造难度曲线。
  • 左右移动，三选一，说清取舍即可：
    • 三车道式：目标 x 只有 −2 / 0 / 2 三个值，按左右键切换目标车道，Mathf.Lerp 平滑移过去。手感干脆，是主流跑酷的做法。
    • 自由滑动式：按住左右键持续加 x 位移，用 Mathf.Clamp(x, -roadHalfWidth, roadHalfWidth) 限制在跑道内。
    • 侧向速度式：给 x 方向一个速度，松开时给阻尼让它回正。
  • 跳跃：GetKeyDown(Space) 触发一次，赋 Y 方向初速度；用射线检测判断是否落地（从脚下向下 Raycast，命中地面才允许跳），防止空中连跳。

④ Trigger 还是普通碰撞体（3 分）

两者都用，按功能分开——这正是这题要考的判断力。

对象用哪种为什么
跑道路块普通碰撞体（不勾 Trigger）必须挡住玩家，否则人会直接穿进地面掉下去
障碍物普通碰撞体撞上去要有阻挡和扣血判定，是「硬的」
金币 / 加速带Trigger（勾 Is Trigger）只需检测玩家经过，不挡路。勾了以后回调走 OnTriggerEnter，参数是 Collider
终点线 / 检查点Trigger穿过去就触发事件，不能让玩家撞停

判断标准一句话：要「挡住」就用普通碰撞体（回调 OnCollisionEnter），只要「检测经过」就用 Trigger（回调 OnTriggerEnter）。两者互斥，同一个碰撞体不可能既阻挡又触发。

按课件口径补一句：发生碰撞的必要条件是一个为刚体、另一个为碰撞体；若要有力的相互作用，则双方都必须有刚体；触发检测只需双方有一个刚体即可。

得分点
  • ① 预制体写出路块、障碍物、玩家、金币、特效；路块不挂刚体
  • ② 说出 无限 vs 有限内存 的矛盾（这一句单独就有 2 分）
  • ② 给出 对象池 + 路段循环复用 + 重新随机内容
  • ③ 前进用 Move/Translate 乘 deltaTime，左右用 Lerp 或 Clamp
  • ③ 跳跃配 射线检测判断落地，防连跳
  • ④ 两种都要用：路块障碍用普通碰撞体，金币终点用 Trigger
