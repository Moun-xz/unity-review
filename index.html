※怎么用按时间倒推的推荐顺序

第一轮 · 建立骨架（约 2 天）
  1. 通读 背诵手册，不求记住，只求知道 8 章分别讲什么。
  2. 对照 代码全解 把四个实验的代码过一遍，重点是 API 名，不是语法。
  3. 翻 组件属性速查清单，只看「设错会怎样」那一栏。
第二轮 · 输出检验（约 2 天）
  1. 用第一、二套（答案常显）当阅读材料，顺着答案学「一道题该怎么写」。
  2. 用第三、四、五套（答案折叠）掐表做，写完一题点一题，错的地方回背诵手册定位。
  3. 编程 15 个空是唯一有确定答案的 30 分，五套合计 75 个空，过两遍就够。
第三轮 · 考前 90 分钟

只看两样：设计题速查表（20 题的技术词）+ 美工专项素材。其余全部合上。考前看新东西只会增加焦虑，不会涨分。

※这门课的出题规律从真题反推

大题分值题源说明
一、案例分析30（5×6）课件 8 章 问法固定为「你是某环节的 ○○，会怎么设计 / 用到什么技术」，正向提问，不考名词解释。美工、粒子、动画、地形、灯光声音五个方向基本各出一题。
二、编程选择30（15 空×2）四个实验 从 A~L 十二个选项里选，挖的都是真实实验代码里的 API 名。主要考玩家控制、声音、刚体、动画。
三、综合设计40（10+15+15）课程设计选题库 不写代码，只讲业务逻辑。给一个游戏需求，问你用什么预制体、什么组件、怎么实现、为什么这么设计。
三条能直接用的经验
  • 写满比写对重要。评分尺度很宽，只要表达出思路就能得分，空着一定是 0 分。写不满时补一段「如果时间允许，我还会……」，这是专业判断，不是凑字数。
  • 设计题一律三层：规则（玩什么、核心决策、怎么算赢）→ 机制（用什么组件和脚本，把技术词写上去）→ 数值（给具体数字，并说明为什么这么调）。
  • 每道题都能指出出处。课件第几章、实验第几步——能指出出处的答案才是有依据的答案，也才敢往卷子上写。
